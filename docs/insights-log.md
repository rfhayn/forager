# Insights Log

**Purpose**: Lightweight capture of technical insights discovered during development sessions. Acts as a triage inbox — when 3+ insights cluster around a topic, promote to a Learning Note or ADR.

**Promotion rules**:
- **3+ related insights** → Learning Note (implementation journey)
- **Architectural decision with trade-offs** → ADR
- **Recurring pattern or gotcha** → Add to CLAUDE.md or development-guidelines.md

Historical insights archived — see git history before March 2026.

| Mar 26 | M16 | Testing/ComparisonLogic | Automated parser comparison (local vs AI) showed 37% agreement on 560 ingredients — alarming until analysis revealed the metric was fundamentally flawed. ~284 "name mismatches" were actually **design differences**: local keeps descriptors ("small onion, diced") while AI normalizes to canonical ("onion"). Neither is wrong. The faulty exact-match comparison buried 7 real parser bugs under 284 false positives. **Lesson: comparison metrics must account for intentional design differences, not just string equality.** Two-tier scoring (core match + full match) separates signal from noise. Before: 37% agreement. After (projected): ~85% core agreement with real issues clearly visible. | Run harness, check "Core agreement" vs "Full agreement" in report | Raw |
| Mar 26 | M16 | Testing/HarnessROI | First automated harness run (42 recipes, 560 ingredients, ~8 min with AI) found 7 real parser bugs that would have taken hours of manual device testing to discover. The harness also accumulated 514 ML training data entries as a byproduct. **Standalone CLI testing of parsing code (no simulator, no device) is transformatively faster than in-app testing.** | Compare time: 8min harness run vs estimated 2+ hours manual testing for equivalent coverage | Raw |
| Mar 26 | M16 | Architecture/SymlinkVsCopy | For experimental code refinement, copying files into a harness (not symlinking) was the right call. | Mar 25 | M9.35.2 | Parsing/RegexBacktracking | Greedy regex `([a-zA-Z]+)?\s*(.+)$` splits short words at character boundaries — "egg" becomes unit="eg", name="g" because the greedy group backtracks just enough for `.+` to match ≥1 char. The recombination then produces "eg g" with a space. **Fix: reject when captured unit is unknown AND remaining name is ≤1 char**, letting the count-noun pattern handle it. General rule: when a greedy group feeds into `.+`, test with 3-4 letter inputs. | Parse "1 egg" → name should be "egg", not "eg g" | Raw |
| Mar 25 | M9.35.2 | Parsing/ConfidenceRouting | Confidence thresholds in multi-tier parser routing are load-bearing architectural decisions. A correct regex parse at 0.70 loses to a wrong ML parse at 0.75 when the hybrid router's auto-accept threshold is 0.9 — both fall through, and the ML result wins on raw confidence. **The confidence value IS the routing decision.** Raising comma-qualifier confidence from 0.70 to 0.92 fixed ~145 prep-in-name instances. | Parse "garlic, crushed" → name "garlic" + notes "crushed" (not "garlic crushed") | Raw |
| Mar 25 | M9.35.2 | Parsing/IEEE754Floats | Recipe sites (AllRecipes) store Unicode fractions like ⅓ as IEEE 754 floats in JSON-LD: `0.33333334326744`. Detection: 8+ digits after decimal (user input never has this precision). Conversion: closest-fraction lookup against 13 common cooking fractions by minimum distance — more robust than exact matching since different platforms produce different float artifacts. | Import AllRecipes recipe with ⅓ cup → displays "1/3 cup" not "0.33333334326744 cup" | Raw |

| Mar 19 | M9.23 | CoreData/InverseRelationshipDirtying | Setting `template.categoryEntity = privateCategory` dirties the Category via its inverse relationship (`ingredientTemplates` set changed). | Mar 16 | M9.21 | CloudKit/DualStoreAsymmetry | On the **owner's** phone, the shared store (`forager_shared.sqlite`) mirrors the shared CloudKit *database* — which contains data shared **by other users with the owner**, NOT the owner's own shared data.
