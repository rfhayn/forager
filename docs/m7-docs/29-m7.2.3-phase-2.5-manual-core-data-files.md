## 📚 **Context**

After building the infrastructure (DataScope, ScopeProvider, Factory) in Phases 2.1-2.4, we needed to activate it by:
1. Uncommenting protocol conformances
2. Activating household logic in factory
3. Adding household/householdKey properties to entity files

The challenge: Core Data model v2 had `householdKey` attributes defined, but Swift entity property files weren't updated to match.

---

## 🎯 **The Problem**

### **Initial Symptom**
Uncommented TODOs in Phase 2.5 → **162 build errors**

**Typical errors**:
```
Cannot find type 'Household' in scope
Cannot find type 'IngredientTemplate' in scope
Cannot find type 'PlannedMeal' in scope
Cannot find type 'MealPlan' in scope
Value of type 'MealPlan' has no member 'completedDate'
```

### **Root Causes**

**Cause 1: Core Data Model ≠ Swift Properties**
- Core Data model v2 had `householdKey` attribute
- Auto-generated Swift files didn't include this property
- Xcode doesn't regenerate files automatically

**Cause 2: Codegen Conflicts**
- Some entities used "Class Definition" codegen
- Created manual property files
- Xcode tried to generate AND use manual files
- Result: "Multiple commands produce" errors

**Cause 3: Missing Entity Files**
- Changed entities to Manual/None codegen
- Only created +CoreDataProperties.swift files
- Forgot +CoreDataClass.swift files
- Compiler couldn't find the base classes

### **Step 5: Fix Preview Syntax**

Swift Preview blocks with explicit `return` statements caused errors:

**Before** (failed):
```swift
#Preview("Active Plan") {
    let context = PersistenceController.preview.container.viewContext
    
    let plan = MealPlan(context: context)
    // ... setup
    
    List {  // ERROR: Type '()' cannot conform to 'View'
        MealPlanRowView(mealPlan: plan, status: .active)
    }
    .environment(\.managedObjectContext, context)
}
```

**After** (works):
```swift
#Preview("Active Plan") {
    @Previewable @State var context = PersistenceController.preview.container.viewContext
    
    let plan = MealPlan(context: context)
    // ... setup
    
    return List {  // EXPLICIT return required
        MealPlanRowView(mealPlan: plan, status: .active)
    }
    .environment(\.managedObjectContext, context)
}
```

**Key changes**:
1. Added `@Previewable @State` for context
2. Added explicit `return` keyword
3. Fixed in 3 preview blocks in MealPlanRowView.swift

## 🎓 **Key Learnings**

### **1. Manual/None Codegen Requires Both Files**

**The Rule**:
- Class Definition: Xcode generates both files automatically
- Manual/None: You must create **both** files manually

**Files Required**:
```
EntityName+CoreDataClass.swift     ← Base class (@objc definition)
EntityName+CoreDataProperties.swift ← Properties & relationships
```

**Common Mistake**: Creating only Properties file → "Cannot find type" errors

---

### **2. Core Data Model ≠ Swift Properties Until Regeneration**

**The Problem**:
- Add attribute to Core Data model
- Xcode doesn't update Swift files automatically
- Code referencing new property fails to compile

**The Solution**:
- Manual/None: Add properties manually to +CoreDataProperties.swift
- Class Definition: Editor → Create NSManagedObject Subclass (regenerate)

**Best Practice**: Verify property files match model XML exactly

---

### **3. Codegen Conflicts Cause "Multiple Commands Produce" Errors**

**Symptom**:
```
Multiple commands produce '/Users/.../DerivedData/.../MealPlan+CoreDataProperties.swift'
```

**Cause**: Entity using Class Definition but manual file also exists

**Solution**: Change entity to Manual/None in Data Model Inspector

---

### **4. Preview Blocks Need Explicit Return for Complex Setup**

**When Previews Work Without Return**:
```swift
#Preview {
    Text("Hello")  // Simple, direct view
}
```

**When Previews Need Return**:
```swift
#Preview {
    let data = prepareData()  // Multi-step setup
    return MyView(data: data)  // Explicit return required
}
```

**Also helps**: `@Previewable @State` for mutable state

---

### **5. Cross-Reference Model XML for Complete Properties**

**Process**:
1. Open `forager.xcdatamodeld/forager 2.xcdatamodel/contents` (XML)
2. Find entity definition
3. List all `<attribute>` and `<relationship>` tags
4. Compare with +CoreDataProperties.swift
5. Add any missing properties

**Example** (from MealPlan):
```xml
<attribute name="completedDate" optional="YES" attributeType="Date" .../>
<attribute name="createdDate" optional="YES" attributeType="Date" .../>
```

Must have corresponding Swift properties:
```swift
@NSManaged public var completedDate: Date?
@NSManaged public var createdDate: Date?
```

## 🚀 **Systematic Debugging Approach**

### **When Build Fails After Core Data Changes**

**Step 1: Identify Error Category**
- "Cannot find type X" → Missing class file
- "No member Y" → Missing property
- "Multiple commands" → Codegen conflict
- "Type () cannot conform" → Preview syntax

**Step 2: Fix One Category at a Time**
- Don't try to fix all 162 errors at once
- Focus on one type of error
- Build → See new error category → Repeat

**Step 3: Verify With Clean Build**
- Clean Build Folder (⌘⇧K)
- Delete DerivedData if persistent issues
- Rebuild (⌘B)

**Step 4: Add Missing Files in Pairs**
- Create +CoreDataClass.swift
- Create +CoreDataProperties.swift
- Add both to Xcode project
- Build to verify

## ⚡ **Quick Reference: Manual Core Data Files**

### **When to Use Manual/None Codegen**

**Use Manual/None when**:
- Need custom logic in entity class
- Want explicit control over properties
- Avoiding codegen conflicts
- Entity referenced circularly by other manual entities

**Use Class Definition when**:
- Simple entity with no custom logic
- No circular references to manual entities
- Want Xcode to manage files

**Forager's Strategy**:
- Household-related entities: Manual/None (for consistency)
- Simple entities (GroceryItem): Class Definition

---

### **Template for +CoreDataClass.swift**

```swift
//
//  EntityName+CoreDataClass.swift
//  forager
//
//  Created on [Date]
//

import Foundation
import CoreData

@objc(EntityName)
public class EntityName: NSManagedObject {
    // Add custom methods here if needed
}
```

---

### **Template for +CoreDataProperties.swift**

```swift
//
//  EntityName+CoreDataProperties.swift
//  forager
//
//  Created on [Date]
//

import Foundation
import CoreData

extension EntityName {

    @nonobjc public class func fetchRequest() -> NSFetchRequest<EntityName> {
        return NSFetchRequest<EntityName>(entityName: "EntityName")
    }

    // Attributes
    @NSManaged public var id: UUID?
    @NSManaged public var name: String?
    // ... all attributes from model
    
    // Relationships
    @NSManaged public var relatedEntity: RelatedEntity?
    // ... all relationships from model
}

// MARK: Generated accessors for to-many relationships
extension EntityName {
    @objc(addRelatedEntitiesObject:)
    @NSManaged public func addToRelatedEntities(_ value: RelatedEntity)
    
    @objc(removeRelatedEntitiesObject:)
    @NSManaged public func removeFromRelatedEntities(_ value: RelatedEntity)
    
    @objc(addRelatedEntities:)
    @NSManaged public func addToRelatedEntities(_ values: NSSet)
    
    @objc(removeRelatedEntities:)
    @NSManaged public func removeFromRelatedEntities(_ values: NSSet)
}

extension EntityName: Identifiable {
}
```

## 💡 **Prevention Strategies**

### **Before Making Core Data Changes**

1. **Plan codegen strategy first**
   - Which entities need Manual/None?
   - Which can stay Class Definition?
   - Document the decision

2. **Create a checklist**
   - [ ] Update Core Data model
   - [ ] Create/update +CoreDataClass.swift
   - [ ] Create/update +CoreDataProperties.swift
   - [ ] Add files to Xcode project
   - [ ] Verify codegen setting matches
   - [ ] Clean build
   - [ ] Build & verify

3. **Update files immediately**
   - Don't let model and code drift
   - Regenerate/update files right after model changes
   - Commit model + files together
