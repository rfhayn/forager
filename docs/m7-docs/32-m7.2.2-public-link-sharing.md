## Problem Statement

**Goal**: Enable household owners to invite members to shared households via CloudKit sharing.

**Original Plan**: Use UICloudSharingController for native contact picker and participant management (Apple's recommended approach for NSPersistentCloudKitContainer).

**What We Discovered**: UICloudSharingController has critical bugs on iOS 18.x that made it unusable.

**Analysis**: The preparationHandler pattern is architecturally correct but doesn't fix the underlying iOS 18.x LaunchServices/XPC service issues.

### Approach 2: UIActivityViewController + One-Time Participant URLs ❌

**Source**: ChatGPT recommendation
**Date**: January 9, 2026 (afternoon)

**Implementation**:

// Attempted approach

### Approach 3: Public Link Sharing + UIActivityViewController ✅

**Source**: Pragmatic pivot based on failed attempts
**Date**: January 9, 2026 (evening)
**Status**: ✅ WORKING

**Implementation**:
```swift
// HouseholdService.swift:519
func createOneTimeInvitationURL(household: Household) async throws -> URL {
    let share = try await getShare(for: household)

    // Enable public link sharing (like Google Docs)
    if share.publicPermission == .none {
        share.publicPermission = .readWrite

        let persistentStore = persistenceController.container
            .persistentStoreCoordinator.persistentStores.first!
        try await persistenceController.container
            .persistUpdatedShare(share, in: persistentStore)
    }

    return share.url!  // This URL now works for anyone
}

// ShareSheet.swift - Simplified to UIActivityViewController
struct ShareSheet: UIViewControllerRepresentable {
    let invitationURL: URL
    var onDismiss: (() -> Void)?

    func makeUIViewController(context: Context) -> UIActivityViewController {
        let controller = UIActivityViewController(
            activityItems: [invitationURL],
            applicationActivities: nil
        )

        controller.completionWithItemsHandler = { _, completed, _, error in
            if completed {
                print("✅ Invitation shared successfully")
            }
            onDismiss?()
        }

        return controller
    }
}

// InviteMemberSheet.swift - Simplified flow
private func presentShareSheet() async {
    isLoading = true
    defer { isLoading = false }

    do {
        let url = try await service.createOneTimeInvitationURL(household: household)
        invitationURL = url
        showingShareSheet = true
    } catch {
        errorMessage = error.localizedDescription
        showingError = true
    }
}
```

## Technical Deep Dive

### Why UICloudSharingController Failed

**Root Cause Analysis**:
1. **iOS 18.x Regression**: Multiple reports of UICloudSharingController flakiness with NSPersistentCloudKitContainer
2. **LaunchServices Error -54**: Sandbox/XPC service communication failure
3. **System-Level Issue**: Not a code problem, not fixable via entitlements
4. **Gemini's preparationHandler**: Correct pattern, but doesn't fix OS-level bug

**Evidence**:
- ChatGPT confirmed: "history of UICloudSharingController behaving inconsistently / 'Add People' issues with Core Data sharing"
- Error symptoms match known LaunchServices sandbox violations
- Same errors persisted across multiple implementation attempts
- No missing entitlements - `CKSharingSupported` was only missing config item

### Why One-Time Participants Failed

**API Reality Check**:
```swift
// What we thought would work (per ChatGPT):
let oneTimeParticipant = CKShare.Participant.oneTimeURLParticipant()
share.participants.append(oneTimeParticipant)  // ❌ participants is read-only
let url = oneTimeParticipant.invitationURL     // ❌ property doesn't exist

// Actual CloudKit API:
public class CKShare : CKRecord {
    public var participants: [CKShare.Participant] { get }  // READ-ONLY!
    public var publicPermission: CKShare.ParticipantPermission
}
```

**Key Learnings**:
1. `CKShare.participants` is **immutable** from client code
2. Participants are added by UICloudSharingController (which we can't use)
3. One-time URL pattern may work with direct CKShare API calls, but not with NSPersistentCloudKitContainer
4. AI recommendations sometimes describe APIs that don't exist in current iOS SDK

### Why Public Link Sharing Works

**Technical Flow**:
1. Fetch existing CKShare from CloudKit (created in M7.2.3 Phase 4)
2. Set `share.publicPermission = .readWrite`
3. Persist updated share via `persistUpdatedShare(share, in: persistentStore)`
4. Share `share.url` via UIActivityViewController
5. Recipient taps URL → CloudKit validates permission → grants access

**CloudKit Behavior**:
- `publicPermission = .none`: URL requires pre-approved participant (UICloudSharingController needed)
- `publicPermission = .readWrite`: URL grants access to anyone (works with UIActivityViewController)

**NSPersistentCloudKitContainer Integration**:
- `persistUpdatedShare()` syncs change to CloudKit
- Share remains associated with Household entity
- Core Data + CloudKit continue to sync normally
- No impact on existing M7.2.3 architecture

## Git Journey & Challenges

### Initial State
- Working code on `main` branch (uncommitted changes)
- Feature branch `feature/M7.2.2-member-invitation` existed with old code

### Attempt 1: Stash and Switch ❌
```bash
git stash
git checkout feature/M7.2.2-member-invitation
git stash pop
# Result: Merge conflicts in all 4 files
```

**Problem**: Feature branch had old UICloudSharingController code that conflicted with new working code.

### Attempt 2: Wrong Conflict Resolution ❌
```bash
git checkout --ours [files]  # Took OLD feature branch code
# Result: Build errors - missing M7.2.3 model properties
```

**Problem**: `--ours` in `stash pop` context means "current branch" (old code), not "stashed changes" (working code).

### Attempt 3: Correct Resolution ✅
```bash
git checkout stash@{0} -- [files]  # Get working code from stash
git commit
git push origin feature/M7.2.2-member-invitation
```

**Result**: Working code committed to feature branch, but still had build errors.

### Attempt 4: Merge Main Failed ❌
```bash
git merge main
# Result: 8 merge conflicts (HouseholdService, PersistenceController, docs, foragerApp)
```

**Problem**: Feature branch too far behind main (missing M7.2.3 Core Data model changes).

### Final Solution: Cherry-Pick to Main ✅
```bash
git checkout main
git cherry-pick e1a467c  # Pick M7.2.2 commit
git checkout --theirs [files]  # Keep M7.2.2 code
git add . && git cherry-pick --continue
git push origin main
```

**Result**:
- ✅ M7.2.2 code on `main` with M7.2.3 infrastructure
- ✅ Build successful
- ✅ Ready for Device B testing

**Key Learning**: When feature branch diverges significantly, cherry-pick specific commits to main rather than merging branches.

## Key Learnings

### Technical Learnings

1. **UICloudSharingController is Fragile**
   - Has known issues with NSPersistentCloudKitContainer
   - LaunchServices/XPC errors are OS-level, not fixable in app code
   - Always have a fallback plan for CloudKit sharing

2. **AI Recommendations Need Verification**
   - ChatGPT suggested APIs that don't exist (one-time participant URLs)
   - Gemini's approach was architecturally correct but didn't fix the bug
   - Always test AI-suggested code against actual SDK documentation

3. **Public Sharing is a Valid Pattern**
   - Used by: Google Docs, Dropbox, Notion, Airtable
   - Trade-off: Convenience vs. granular control
   - For family/friend apps: Public links are acceptable with good messaging

4. **NSPersistentCloudKitContainer is Powerful but Limited**
   - Great for automatic sync
   - Limited control over CKShare participant management
   - `persistUpdatedShare()` is the key for share modifications

5. **Git Conflict Resolution Requires Care**
   - In `stash pop`: `--ours` = current branch, `--theirs` = stashed changes
   - Cherry-picking is cleaner than merging diverged branches
   - When in doubt: work on main, use feature branches for experiments only

### Process Learnings

1. **External AI Consultation is Valuable**
   - Gemini provided preparationHandler pattern (correct approach)
   - ChatGPT confirmed UICloudSharingController issues (known problem)
   - Both helped rule out approaches quickly

2. **Pragmatic Pivots > Perfect Solutions**
   - Spent 4 hours on UICloudSharingController (failed)
   - Spent 2 hours on one-time participants (failed)
   - Spent 1 hour on public link sharing (success)
   - Sometimes the "hacky" solution is the right solution

3. **Testing on Real Devices is Essential**
   - Simulator would have hidden LaunchServices errors
   - Real iCloud accounts required for CloudKit testing
   - Physical devices show the actual user experience

4. **Git Hygiene Matters**
   - Commit working code immediately
   - Don't mix feature branches with large main branch changes
   - Document tricky conflict resolutions
