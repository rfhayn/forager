## 1. Problem Statement

When users import recipes (URL, text paste, or photo), each ingredient needs a grocery category (Fruits & Veg, Deli & Meat, Dairy, etc.) for proper grocery list organization. Currently, category assignment relies on:

1. **Template matching** — if the ingredient was seen before and categorized, it auto-fills
2. **Inline category pickers** — user manually selects from a dropdown during import preview
3. **CategoryAssignmentModal** — fallback for any remaining uncategorized ingredients

For new users, the template library is empty — every ingredient in their first import requires manual categorization. This creates significant friction during onboarding. As the library grows through use, the burden decreases, but the first-use experience is poor.

## 2. Solution

Pre-seed the `IngredientTemplate` database with ~1,500-2,000 common grocery ingredients, each pre-assigned to one of Forager's 7 grocery categories. Source data comes from the **USDA FoodData Central** public domain datasets.

After seeding, a user's first recipe import would have most ingredients auto-categorized, dramatically reducing manual work.

## 3. Data Source: USDA FoodData Central

## 4. Name Cleaning Pipeline

USDA names follow an inverted, verbose convention unsuitable for recipe matching:

```
USDA:    "Chicken, broilers or fryers, drumstick, meat only, raw"
Forager: "chicken drumstick"

USDA:    "Cheese, cheddar, sharp, sliced"
Forager: "cheddar cheese"

USDA:    "Broccoli, raw"
Forager: "broccoli"
```

### 4.1 Cleaning Steps

1. **Split on commas** — parse into primary noun + qualifiers
2. **Strip preparation qualifiers** — remove: raw, cooked, boiled, baked, fried, drained, grilled, roasted, steamed, frozen, canned, dried, dehydrated, unprepared, prepared
3. **Strip USDA-specific qualifiers** — remove: separable lean only, bone-in, boneless, with bone, meat only, meat and skin, with salt added, without salt, enriched, unenriched, bleached, unbleached, pasteurized, homogenized
4. **Strip size/form qualifiers** — remove: sliced, diced, chopped, whole, halves, pieces, ground, minced, shredded, cubed, crushed, mashed
5. **Invert primary noun** — "Cheese, cheddar" → "cheddar cheese"
6. **Title case normalize** — lowercase everything for template matching
7. **Deduplicate** — group by cleaned name, keep the most common USDA category assignment

## 6. Design Considerations

### 6.1 User-Created vs Seeded Templates

Need a way to distinguish templates the user created from system-seeded ones:
- Option A: Add `isSystemSeeded: Bool` attribute to IngredientTemplate (requires schema change)
- Option B: Add a `source` string attribute ("usda", "user", "import")
- Option C: No distinction — treat all templates equally

**Recommendation**: Option C for launch. The seeded templates behave identically to user-created ones. If the user recategorizes an ingredient, their choice persists. Simplest approach, no schema change.

### 6.2 Frozen Category Gap

Forager has a "Frozen" category, but USDA doesn't distinguish fresh vs frozen at the category level (frozen broccoli is still "Vegetables"). Options:
- Ignore — most recipe ingredients are fresh; users buying frozen can recategorize
- Heuristic — items with "frozen" in the USDA name get mapped to Frozen category
- Manual overrides — curate a list of commonly-frozen items

**Recommendation**: Heuristic + manual overrides. Items with "frozen" in the cleaned name get Frozen category. A small manual override list handles known frozen staples.

### 6.3 International Ingredients

USDA data is US-centric. Common international ingredients (paneer, gochujang, tahini, miso, etc.) may be missing. Options:
- Accept the gap for launch — users categorize these manually
- Supplement with a hand-curated international ingredients list
- Use M10.6 LLM integration to categorize unknown ingredients on-the-fly

**Recommendation**: Accept for launch. M10.6 LLM integration handles the long tail. The seed dictionary covers the 80% case; LLM covers the rest.
