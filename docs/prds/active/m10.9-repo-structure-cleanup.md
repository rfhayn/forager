## Problem

The forager repo root directory has **46 items** visible on GitHub — 37 of which are Core Data entity Swift files that accumulated over M1-M7. This makes the repo look cluttered and unprofessional, especially as a first impression on GitHub. The `forager/` app directory also has **54 Swift files** in a flat list with no subdirectories (except `Repositories/`).

### Current Root Directory (46 items)
| Category | Count | Description |
|----------|-------|-------------|
| Core Data generated files | 24 | `+CoreDataClass.swift`, `+CoreDataProperties.swift` for all 12 entities |
| Core Data extension files | 12 | `+Extensions.swift`, `+ComputedProperties.swift`, `+Validation.swift` |
| Dead code | 1 | `MigrationTestHelper.swift` (temporary M7.1.3 utility, never removed) |
| Standard files | 3 | `CLAUDE.md`, `LICENSE`, `README.md` |
| Directories | 6 | `forager/`, `foragerTests/`, `foragerUITests/`, `Services/`, `Tools/`, `docs/` |

### Why Core Data Files Ended Up at Root
Xcode's "Create NSManagedObject Subclass" defaults output to the project root for `Manual/None` codegen entities. Over 12 entities x 2-4 files each, this grew to 37 files. The `Services/` directory avoided this problem because it uses `PBXFileSystemSynchronizedRootGroup` (auto-sync), while root files use individual `PBXFileReference` entries.

#### pbxproj Changes (convert to auto-sync)

1. Create `Models/` directory on disk
2. `git mv` all 36 files into `Models/`
3. In `project.pbxproj`:
   - Add new `PBXFileSystemSynchronizedRootGroup` entry for `Models/` (copy pattern from `Services/` entry at ID `9BADD71F2E64E79A00D677DC`)
   - Add `PBXFileSystemSynchronizedBuildFileExceptionSet` linking Models to main app target
   - Remove all 36 individual `PBXFileReference` entries (IDs listed in analysis below)
   - Remove all 36 individual `PBXBuildFile` entries
   - Remove 36 file IDs from root `PBXGroup` children array (ID `9B731C202E535C3100CE26F0`)
   - Add new `Models` group ID to root `PBXGroup` children

This makes `Models/` auto-synced like `Services/`, so future entity files added there are picked up automatically by Xcode.

#### pbxproj Changes (convert to auto-sync)

Same strategy as Tier 1: convert `forager/` from manual `PBXGroup` to `PBXFileSystemSynchronizedRootGroup`. This eliminates ~60 individual `PBXFileReference` + `PBXBuildFile` entries and makes all future file additions automatic.

**Added complexity:** `forager/` contains resource bundles that need proper build phase handling:
- `.xcdatamodeld` (Core Data model bundle)
- `.xcassets` (asset catalog)
- `.mlpackage` (CoreML model)
- `.storyboard` (launch screen)

The `PBXFileSystemSynchronizedBuildFileExceptionSet` needs entries for these resource types to route them to the correct build phases (Resources vs Sources).
