# M10.8: Inline Ingredient Editing — Display/Edit Toggle for Recipe Views

**Status**: ACTIVE
**Milestone**: M10.8
**Branch**: `feature/M10.8-inline-ingredient-editing`
**Depends on**: M10.3 (photo import — pattern source validated)
**Estimated**: 4-6 hours (1 sub-phase, 3 files)
**Last Updated**: February 28, 2026

---

## §1 Overview

### 1.1 Problem Statement

`EditRecipeView` and `CreateRecipeView` have broken ingredient editing:

1. **Crash on open**: `formattedIngredientText()` calls `parsingService.parseIngredient()` during view body evaluation, which mutates `@Published var lastParsingDuration` on the `@StateObject` — triggering "Publishing changes from within view updates" and an infinite re-render crash.

2. **Tap gestures don't work**: The ingredient list uses `List` with `.environment(\.editMode, .constant(.active))` for drag/delete, but List in active edit mode intercepts all tap gestures before they reach child views — making tap-to-edit impossible.

3. **Inconsistency with import flow**: `RecipeImportPreviewView` has a polished display/edit toggle (tap-to-edit, formatted read-only display, bordered cards) that works correctly. The recipe editing views should match this behavior exactly.

4. **Unnecessary "Edit" button**: `RecipeDetailView` has an "Edit" toolbar button that opens `EditRecipeView` as a sheet. Since all fields in EditRecipeView are directly tappable/editable (title, servings, ingredients, instructions), a separate "Edit" button is unnecessary navigation friction. The user should be able to start editing from the detail view directly.

### 1.2 Solution

Replace the broken `List`-based ingredient section with the **exact same architecture** used in `RecipeImportPreviewView`:

- **ScrollView + VStack + ForEach** instead of `List` (eliminates gesture conflicts)
- **Pre-computed ingredient matches** via `.task {}` / `.onAppear` (eliminates render-time `@Published` mutation)
- **Bordered card rows** with accent highlight when editing (matches import visual style)
- **`.onTapGesture`** on formatted text (works correctly without List interference)
- **Swipe-to-delete via `.swipeActions`** on individual rows (replaces List `.onDelete`)
- **Remove the "Edit" button** from `RecipeDetailView` toolbar — edit is the sheet's entire purpose, no separate mode needed

### 1.3 Design Principles

- **True pattern reuse** — port the `RecipeImportPreviewView` ingredient architecture, not just the UI concept
- **Pre-compute, don't render-parse** — never call `parseIngredient()` during view body evaluation
- **No List for ingredient rows** — use VStack + ForEach like the import view does
- **Service change required** — remove `@Published` mutation from the lightweight `parseIngredient()` method
- **Minimal scope** — 3 files modified, no new files

## §2 Architecture

### 2.1 Key Lessons from Failed Attempt

The original PRD made three incorrect assumptions:

| Assumption | Reality |
|-----------|---------|
| "`.editMode(.active)` coexists with tap gestures" | List in active edit mode intercepts ALL taps for selection/reorder — `onTapGesture` and `Button` inside rows don't fire |
| "`parseIngredient()` is safe to call during render" | It mutates `@Published var lastParsingDuration`, causing "Publishing changes from within view updates" crash |
| "Zero service changes needed" | Must remove `@Published` mutation from the lightweight parse path, and must pre-compute matches like the import view does |

### 2.2 Pattern Source — RecipeImportPreviewView

The working implementation in `RecipeImportPreviewView` (lines 448-580) uses:

| Mechanism | Import View Implementation |
|-----------|---------------------------|
| Container | `ScrollView` → `VStack` → `ForEach(indices)` — **not** a `List` |
| Match state | `@State ingredientMatches: [Int: IngredientMatchInfo]` — pre-computed in `.task {}` |
| Display rendering | `formattedIngredientText(text:matchInfo:)` — reads from pre-computed dict, never calls parser |
| Tap to edit | `.onTapGesture { editingIndex = index }` — works because no List intercepting |
| Row visual | Bordered card: `.overlay(RoundedRectangle)` with accent stroke when editing |
| Edit tracking | `@State editingIndex: Int?` |
| Focus tracking | `@FocusState focusedIngredient: Int?` |
| Commit on exit | `reMatchIngredient(index:)` — re-parses + template-matches when leaving a row |

### 2.3 Adaptation for Recipe Views

Recipe views use `IngredientInput` (with `UUID` id) instead of raw string arrays, so tracking is UUID-based:

| Concept | Import Preview | Recipe Views |
|---------|---------------|-------------|
| Edit tracking | `@State editingIndex: Int?` | `@State editingIngredientId: UUID?` |
| Focus tracking | `@FocusState focusedIngredient: Int?` | `@FocusState focusedIngredientId: UUID?` |
| Match state | `[Int: IngredientMatchInfo]` | `[UUID: IngredientMatchInfo]` keyed by `IngredientInput.id` |
| Commit | `reMatchIngredient(index:)` | `commitIngredientEdit(for:)` |
| Delete | Not supported | Swipe action on each row card |

### 2.4 State Management

```swift
// Pre-computed match info per ingredient (avoids parsing during render)
private struct IngredientMatchInfo {
    let parsedName: String
    let status: IngredientStatus
    let categoryName: String?
}

@State private var ingredientMatches: [UUID: IngredientMatchInfo] = [:]
@State private var editingIngredientId: UUID?
@FocusState private var focusedIngredientId: UUID?
```

### 2.5 Pre-Compute Ingredient Matches

Called on `.onAppear` and after any edit commit — **never during body evaluation**:

```swift
private func computeIngredientMatches() {
    var matches: [UUID: IngredientMatchInfo] = [:]
    for ingredient in formData.ingredients {
        let text = ingredient.fullText.trimmingCharacters(in: .whitespacesAndNewlines)
        guard text.count >= 2 else { continue }

        let parsed = parsingService.parseIngredient(text: text)
        let cleanName = parsed.displayName
        let candidates = templateService.searchTemplates(query: cleanName, limit: 5)
        let exactMatch = candidates.first(where: {
            $0.name?.lowercased() == cleanName.lowercased()
        })

        let status: IngredientStatus
        let categoryName: String?
        if let template = exactMatch {
            if let category = template.category, !category.isEmpty,
               category.lowercased() != "uncategorized" {
                status = .ready
                categoryName = category
            } else {
                status = .needsCategory
                categoryName = nil
            }
        } else {
            status = .needsTemplate
            categoryName = nil
        }

        matches[ingredient.id] = IngredientMatchInfo(
            parsedName: cleanName, status: status, categoryName: categoryName
        )
    }
    ingredientMatches = matches
}
```

### 2.6 Ingredient Section — VStack + ForEach (Not List)

Replace the current `List { ForEach ... }.environment(\.editMode, .constant(.active))` with:

```swift
VStack(spacing: ForagerTheme.Spacing.sm) {
    ForEach(Array(formData.ingredients.enumerated()), id: \.element.id) { index, ingredient in
        ingredientRow(ingredient: ingredient, index: index)
    }
}
```

No `List`, no `.editMode`, no gesture conflicts.

### 2.7 Ingredient Row — Bordered Card with Display/Edit Toggle

Each row is a bordered card matching the import view style:

```swift
private func ingredientRow(ingredient: IngredientInput, index: Int) -> some View {
    let isEditing = editingIngredientId == ingredient.id
    let matchInfo = ingredientMatches[ingredient.id]

    return VStack(alignment: .leading, spacing: ForagerTheme.Spacing.xs) {
        HStack(spacing: ForagerTheme.Spacing.sm) {
            // Status indicator
            statusIcon(for: ingredient, matchInfo: matchInfo)

            if isEditing {
                // Edit mode: TextField
                TextField("Ingredient", text: ingredientBinding(for: ingredient))
                    .font(ForagerTheme.bodyFont)
                    .autocorrectionDisabled()
                    .submitLabel(.done)
                    .focused($focusedIngredientId, equals: ingredient.id)
                    .onSubmit {
                        commitIngredientEdit(for: ingredient)
                        editingIngredientId = nil
                    }
            } else {
                // Display mode: formatted text from pre-computed match
                formattedIngredientText(for: ingredient, matchInfo: matchInfo)
                    .frame(maxWidth: .infinity, minHeight: 24, alignment: .leading)
                    .contentShape(Rectangle())
                    .onTapGesture {
                        editingIngredientId = ingredient.id
                    }
            }
        }

        // Category label below the ingredient text
        if let category = matchInfo?.categoryName {
            Text(category)
                .font(ForagerTheme.captionFont)
                .foregroundStyle(ForagerTheme.textSecondary)
                .padding(.leading, 22)
        } else {
            Text("New ingredient - needs category")
                .font(ForagerTheme.captionFont)
                .foregroundStyle(ForagerTheme.statusWarningFG)
                .padding(.leading, 22)
        }
    }
    .padding(.vertical, ForagerTheme.Spacing.sm)
    .padding(.horizontal, ForagerTheme.Spacing.md)
    .background(ForagerTheme.surfacePrimary)
    .overlay(
        RoundedRectangle(cornerRadius: ForagerTheme.Radius.sm)
            .stroke(isEditing ? ForagerTheme.accentPrimary : ForagerTheme.borderSubtle, lineWidth: 1)
    )
    .clipShape(RoundedRectangle(cornerRadius: ForagerTheme.Radius.sm))
    // Swipe to delete (replaces List .onDelete)
    .swipeActions(edge: .trailing) {
        Button(role: .destructive) {
            formData.ingredients.removeAll(where: { $0.id == ingredient.id })
            ingredientMatches.removeValue(forKey: ingredient.id)
            hasUnsavedChanges = true
        } label: {
            Label("Delete", systemImage: "trash")
        }
    }
}
```

**Note on swipe actions**: `.swipeActions` requires a `List` or `ForEach` inside a `List` context. Since we're using plain `VStack` + `ForEach`, swipe-to-delete must be implemented differently — either with a trailing delete button per row, a long-press context menu, or by keeping a simple delete icon at the trailing edge. The exact deletion UX is flexible; the priority is that tap-to-edit works.

### 2.8 Formatted Text — Reads from Pre-Computed Match, No Parse

```swift
private func formattedIngredientText(for ingredient: IngredientInput, matchInfo: IngredientMatchInfo?) -> Text {
    let text = ingredient.fullText.trimmingCharacters(in: .whitespacesAndNewlines)
    guard let info = matchInfo else {
        return Text(text).font(ForagerTheme.bodyFont).foregroundColor(ForagerTheme.textPrimary)
    }

    if let range = text.range(of: info.parsedName, options: .caseInsensitive) {
        let prefix = String(text[text.startIndex..<range.lowerBound])
        let name = String(text[range])
        let suffix = String(text[range.upperBound...])
        return Text(prefix).font(ForagerTheme.bodyFont).foregroundColor(ForagerTheme.textSecondary)
            + Text(name).font(ForagerTheme.bodyFont).bold().foregroundColor(ForagerTheme.accentPrimary)
            + Text(suffix).font(ForagerTheme.bodyFont).foregroundColor(ForagerTheme.textSecondary)
    }

    return Text(text).font(ForagerTheme.bodyFont).foregroundColor(ForagerTheme.textPrimary)
}
```

### 2.9 Commit + Re-Compute on Edit Exit

```swift
private func commitIngredientEdit(for ingredient: IngredientInput) {
    guard let index = formData.ingredients.firstIndex(where: { $0.id == ingredient.id }) else { return }
    let text = formData.ingredients[index].fullText
    guard text.count >= 2 else { return }

    // Re-parse and template-match
    let parsed = parsingService.parseIngredient(text: text)
    let existingTemplate = templateService.searchTemplates(query: parsed.name, limit: 1)
        .first(where: { $0.name?.lowercased() == parsed.name.lowercased() })
    formData.ingredients[index].template = existingTemplate
    hasUnsavedChanges = true

    // Update pre-computed match for this ingredient
    let status: IngredientStatus
    let categoryName: String?
    if let template = existingTemplate {
        if let category = template.category, !category.isEmpty {
            status = .ready
            categoryName = category
        } else {
            status = .needsCategory
            categoryName = nil
        }
    } else {
        status = .needsTemplate
        categoryName = nil
    }
    ingredientMatches[ingredient.id] = IngredientMatchInfo(
        parsedName: parsed.displayName, status: status, categoryName: categoryName
    )
}
```

### 2.10 Focus Synchronization

Same two `.onChange` handlers, unchanged from original PRD:

```swift
.onChange(of: editingIngredientId) { oldValue, newValue in
    if let oldId = oldValue, oldId != newValue,
       let ingredient = formData.ingredients.first(where: { $0.id == oldId }) {
        commitIngredientEdit(for: ingredient)
    }
    focusedIngredientId = newValue
}

.onChange(of: focusedIngredientId) { _, newValue in
    if newValue == nil, let editingId = editingIngredientId,
       let ingredient = formData.ingredients.first(where: { $0.id == editingId }) {
        commitIngredientEdit(for: ingredient)
        editingIngredientId = nil
    }
}
```

### 2.11 Service Fix — Remove @Published Mutation from Lightweight Parse

`IngredientParsingService.parseIngredient(text:)` must NOT mutate `@Published` properties. It is called from `computeIngredientMatches()` which may run during `.onAppear` or from `commitIngredientEdit()`. The method is documented as "Lightweight — no telemetry" but was setting `self.lastParsingDuration`, causing the crash.

**Fix**: Remove the timing/publish from `parseIngredient()`:

```swift
// Before (broken):
func parseIngredient(text: String) -> ParsedIngredient {
    let startTime = CFAbsoluteTimeGetCurrent()
    let result = parser.parse(text)
    let duration = CFAbsoluteTimeGetCurrent() - startTime
    self.lastParsingDuration = duration  // ← CRASH: mutates @Published during render
    return Self.mapToParsedIngredient(result)
}

// After (fixed):
func parseIngredient(text: String) -> ParsedIngredient {
    let result = parser.parse(text)
    return Self.mapToParsedIngredient(result)
}
```

The `@Published var lastParsingDuration` is still set by `parseCore()` which is used for final telemetry-logged operations (not called during rendering).

## §4 Files Modified

### 4.0 Implementation Pivot (v3)

**Original scope** (v1-v2): EditRecipeView + CreateRecipeView — fix broken List-based ingredient editing with `IngredientInput` form models.

**Actual scope** (v3): RecipeDetailView — add inline ingredient editing directly on the detail page using live Core Data `Ingredient` objects. This is a fundamentally different data model:

| Aspect | Original (v2) | Actual (v3) |
|--------|---------------|-------------|
| Target view | EditRecipeView, CreateRecipeView | RecipeDetailView |
| Data model | `IngredientInput` form structs | Core Data `Ingredient` objects |
| Save model | Buffer all changes → batch save | Save-per-ingredient on blur |
| Key type | `UUID` from `IngredientInput.id` | `UUID` from `Ingredient.id` |
| Edit text buffer | `IngredientInput.fullText` (mutable) | `@State editedTexts: [UUID: String]` |
| Category persistence | Via `onSave` callback | Immediate via `templateService.updateCategory()` |
| Scaling interaction | N/A | Disable editing at non-1x scale |

**Lesson**: The PRD was drafted before sufficient exploration of the RecipeDetailView's data flow. Planning should have included reading the target view code to identify these differences.

## §5 Interaction Design

### 5.1 Row States

| State | Visual | Trigger |
|-------|--------|---------|
| **Display** (default) | Bordered card. Formatted text: qty+unit secondary, name bold accent. Category caption below. Status icon left. | Row not being edited |
| **Editing** | Same bordered card with accent-colored border. Plain TextField with cursor. | Tap on display row |
| **Committing** | Brief — re-parse + template match + update match cache | Submit (keyboard done), tap another row, tap outside |

### 5.2 Delete UX

Since `List` is removed, `.swipeActions` is not available. Delete is handled via:
- **Context menu** (long-press) with a "Delete" option, OR
- **Trailing delete icon** visible in each row

Choose whichever is simpler to implement. The priority is that tap-to-edit works without gesture conflicts.

## §9 Phase 2: Fully Inline RecipeDetailView + Import Instructions Editing

**Status**: COMPLETE (implemented in v4)

### 9.1 Overview

Phase 2 eliminates the Edit Recipe modal entirely by making everything inline-editable on the detail page. Also adds instruction editing to the import preview view, matching the same bordered-card tap-to-edit pattern.

### 9.2 Inline Instruction Editing — RecipeDetailView

| Element | Implementation |
|---------|---------------|
| State | `editingStepIndex: Int?`, `editedSteps: [Int: String]`, `@FocusState focusedStepIndex: Int?` |
| Computed steps | `currentInstructionSteps` — splits `recipe.instructions` by newline, strips numbering via `cleanStepText()` |
| Display mode | Bordered card per step: number badge + text. Tap → TextField |
| Edit mode | `TextField("Step N", text:, axis: .vertical)` with `.submitLabel(.done)`. Commit on submit or focus loss |
| Add step | "+ Add Step" button appends placeholder, enters edit mode |
| Delete step | Context menu → rebuild instructions without that step |
| Commit | `commitSingleStepEdit(index:)` — rebuild joined string → `recipeServiceM75.updateRecipe(recipe, instructions:)` |

### 9.3 Inline Instruction Editing — RecipeImportPreviewView

Same bordered-card pattern as RecipeDetailView with key differences:

- Writes to `draft.instructions.value` (buffered until Save), not Core Data
- Keeps collapse behavior (show 3 / show all); auto-expands when editing
- Mutual exclusion with ingredient editing: setting `editingStepIndex` clears `editingIndex` and vice versa

### 9.4 Inline Metadata Editing — RecipeDetailView

| Field | Behavior |
|-------|----------|
| Title | Tap text → `TextField` with `.detailTitle` font. Submit/blur → `updateRecipe(recipe, title:)` |
| Favorite | Heart icon always visible (filled/outline). Tap → `toggleFavorite(recipe)` — instant, no edit mode |
| Prep/Cook time | Tap label → inline `TextField` with `.numberPad`. Blur → `updateRecipe(recipe, prepTime:/cookTime:)`. Shows "Prep"/"Cook" placeholder when 0 |
| Servings | Tap text → inline `TextField` with `.numberPad`. Blur → `updateRecipe(recipe, servings:)` |

Focus management: `MetadataFocus` enum with `@FocusState` — setting any metadata focus auto-nils ingredient/step focus via SwiftUI's single-active-focus behavior, triggering their commit handlers.

### 9.5 Edit Recipe Modal Removed

- Removed `showingEditSheet` state, `.sheet(isPresented:)`, "Edit Recipe" menu item, `onChange(of: showingEditSheet)` handler
- `EditRecipeView.swift` left as dead code (cleanup deferred)

### 9.6 Category Picker Height Fix

Both RecipeDetailView and RecipeImportPreviewView: `.presentationDetents([.medium])` → `.presentationDetents([.medium, .large])` — allows dragging the sheet taller when many categories exist.
