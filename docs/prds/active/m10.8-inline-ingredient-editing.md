## §1 Overview

### 1.1 Problem Statement

`EditRecipeView` and `CreateRecipeView` display always-visible TextFields for every ingredient row. This creates several UX issues:

- **No visual distinction between reading and editing** — the ingredient list looks like a form at all times, even when the user is scrolling or reviewing
- **Cluttered appearance** — raw `"2 cups all-purpose flour"` text in plain TextFields lacks the polished formatting users see elsewhere in the app
- **Inconsistency with import flow** — `RecipeImportPreviewView` already has a refined display/edit toggle (tap-to-edit, formatted read-only display) that was built and validated during M10.3. The recipe editing views should match this quality level

### 1.2 Solution

Apply the `RecipeImportPreviewView` ingredient row pattern to `EditRecipeView` and `CreateRecipeView`:

- **Default state**: Formatted read-only display — quantity+unit in secondary color, parsed ingredient name bold in accent color
- **Edit state**: Tap a row to switch to a TextField for that single ingredient; keyboard focus via `@FocusState`
- **Commit on exit**: Re-parse + template-match when the user submits or taps away

### 1.3 Design Principles

- **Zero new files** — modify 2 existing view files only
- **Zero model/service changes** — `IngredientInput`, `RecipeFormData`, parsing service, template service are all unchanged
- **Pattern reuse** — directly port the proven `RecipeImportPreviewView` approach
- **Drag/delete preserved** — `.editMode(.active)` stays for reorder and swipe-to-delete compatibility
- **No new dependencies** — pure SwiftUI state management

## §2 Architecture

### 2.1 Pattern Source

The implementation pattern is fully validated in `RecipeImportPreviewView` (built during M10.3). The key mechanisms:

| Concept | Import Preview (source) | Recipe Views (target) |
|---------|------------------------|----------------------|
| Edit tracking | `@State editingIndex: Int?` | `@State editingIngredientId: UUID?` |
| Focus tracking | `@FocusState focusedIngredient: Int?` | `@FocusState focusedIngredientId: UUID?` |
| Display rendering | `formattedIngredientText()` | Same function, adapted for `IngredientInput` |
| Commit on exit | `reMatchIngredient(index:)` | `commitIngredientEdit(for:)` |
| Focus sync | `.onChange(of: editingIndex)` | `.onChange(of: editingIngredientId)` |

**Key difference**: Recipe views use `UUID`-based tracking (via `IngredientInput.id`) rather than integer indices, because the ingredient list supports reordering and deletion which would invalidate index-based tracking.

### 2.2 State Management

Add to both `EditRecipeView` and `CreateRecipeView`:

```swift
@State private var editingIngredientId: UUID?
@FocusState private var focusedIngredientId: UUID?
```

### 2.3 Display Mode — Formatted Ingredient Text

When `editingIngredientId != ingredient.id`, render a formatted `Text` view:

```swift
private func formattedIngredientText(for ingredient: IngredientInput) -> Text {
    let text = ingredient.fullText.trimmingCharacters(in: .whitespacesAndNewlines)
    let parsed = parsingService.parseIngredient(text: text)

    // Build "2 cups " (secondary) + "flour" (bold accent) + " sifted" (secondary)
    let name = parsed.displayName
    if let range = text.lowercased().range(of: name.lowercased()) {
        let prefix = String(text[text.startIndex..<range.lowerBound])
        let matched = String(text[range])
        let suffix = String(text[range.upperBound...])

        return Text(prefix).foregroundColor(ForagerTheme.textSecondary)
             + Text(matched).bold().foregroundColor(ForagerTheme.accentPrimary)
             + Text(suffix).foregroundColor(ForagerTheme.textSecondary)
    }

    // Fallback: show full text with parsed name indicator
    return Text(text).foregroundColor(ForagerTheme.textPrimary)
}
```

### 2.4 Edit Mode — TextField with Focus

When `editingIngredientId == ingredient.id`, show a `TextField`:

```swift
TextField("Ingredient", text: ingredientBinding(for: ingredient))
    .font(.body)
    .textFieldStyle(PlainTextFieldStyle())
    .focused($focusedIngredientId, equals: ingredient.id)
    .submitLabel(.done)
    .onSubmit {
        commitIngredientEdit(for: ingredient)
        editingIngredientId = nil
    }
```

### 2.5 Commit on Edit Exit

Re-parse and template-match when leaving edit mode:

```swift
private func commitIngredientEdit(for ingredient: IngredientInput) {
    guard let index = formData.ingredients.firstIndex(where: { $0.id == ingredient.id }) else { return }
    let text = formData.ingredients[index].fullText
    guard text.count >= 2 else { return }

    let parsed = parsingService.parseIngredient(text: text)
    let existingTemplate = templateService.searchTemplates(query: parsed.name, limit: 1)
        .first(where: { $0.name?.lowercased() == parsed.name.lowercased() })
    formData.ingredients[index].template = existingTemplate
    hasUnsavedChanges = true
}
```

### 2.6 Focus Synchronization

Two `.onChange` handlers keep state and focus in sync:

```swift
.onChange(of: editingIngredientId) { oldValue, newValue in
    // Re-match when leaving an ingredient row
    if let oldId = oldValue, oldId != newValue,
       let ingredient = formData.ingredients.first(where: { $0.id == oldId }) {
        commitIngredientEdit(for: ingredient)
    }
    // Sync focus to editing state
    focusedIngredientId = newValue
}

.onChange(of: focusedIngredientId) { _, newValue in
    // When tapped away (focus lost), auto-exit edit mode
    if newValue == nil, let editingId = editingIngredientId,
       let ingredient = formData.ingredients.first(where: { $0.id == editingId }) {
        commitIngredientEdit(for: ingredient)
        editingIngredientId = nil
    }
}
```

## §4 Interaction Design

### 4.1 Row States

| State | Visual | Trigger |
|-------|--------|---------|
| **Display** (default) | Formatted text: qty+unit secondary, name bold accent. Category caption below. Status indicator left. | Row not being edited |
| **Editing** | Plain TextField with cursor. Same caption/status below. Accent border highlight. | Tap on display row |
| **Committing** | Brief — re-parse + template match | Submit (keyboard done), tap another row, tap outside |

### 4.2 Row Transition Flow

```
User sees formatted ingredient list
  │
  ├─ Tap row → editingIngredientId = row.id → @FocusState activates keyboard
  │             TextField appears with full text
  │
  ├─ User types edits
  │
  ├─ User taps "Done" on keyboard
  │   → .onSubmit fires
  │   → commitIngredientEdit() re-parses + template-matches
  │   → editingIngredientId = nil → row returns to formatted display
  │
  ├─ User taps a different row
  │   → .onChange(of: editingIngredientId) fires for old row
  │   → commitIngredientEdit() for old row
  │   → New row becomes editing
  │
  └─ User taps outside ingredient list
      → .onChange(of: focusedIngredientId) detects nil
      → commitIngredientEdit() for current row
      → editingIngredientId = nil
```

### 4.3 Drag/Delete Compatibility

The ingredient list uses `.environment(\.editMode, .constant(.active))` for reorder handles and swipe-to-delete. This must be preserved. The display/edit toggle operates within each row's content — it does not interfere with List edit mode.

## §6 Risks & Mitigations

| Risk | Likelihood | Mitigation |
|------|-----------|------------|
| `@FocusState` not syncing with List editMode | Low | M10.3 validated this exact pattern; `.editMode(.active)` coexists with `@FocusState` |
| Formatted text wrapping differently than TextField | Low | Both use `.body` font; formatted text may wrap differently due to `Text` concatenation. Test with long ingredients. |
| Performance with many ingredients (>20) | Very Low | `formattedIngredientText()` calls `parseIngredient()` which is <0.05s; only called per-row render |
