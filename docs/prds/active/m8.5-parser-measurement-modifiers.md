# M8.5: Parser Measurement Modifier Stripping

**Status**: ACTIVE
**Estimated**: 30 min
**Discovered**: M9.15.3 session — diagnostic log showed `extractCleanIngredientName("2 heaping tablespoons tomato paste")` returning "Heaping Tablespoons Tomato Paste" instead of "Tomato Paste", creating spurious templates

## Problem

`RegexIngredientParser.tryStandardPatternInternal` captures the first word after qty as a potential unit. When that word is a measurement modifier (e.g., "heaping"), it fails `isKnownUnit` and gets folded into the ingredient name:

```
"2 heaping tablespoons tomato paste"
  → qty=2, unit="heaping" (not known), name="tablespoons tomato paste"
  → final name: "heaping tablespoons tomato paste"
```

This causes: (1) wrong ingredient names, (2) spurious template creation, (3) category loss when template re-lookup doesn't match the original.

## Solution

Add a text preprocessing step in `RegexIngredientParser.parse()` that strips measurement modifiers appearing between a quantity and a known unit:

```
"2 heaping tablespoons tomato paste" → "2 tablespoons tomato paste"
```

Modifiers: heaping, rounded, scant, generous, level, packed, lightly, loosely, firmly, overflowing

## Scope

- **Change**: `RegexIngredientParser.swift` — add `stripMeasurementModifiers()` preprocessing
- **Tests**: Add test cases for modifier stripping in existing parser test file
- **No schema changes**, no migration, no UI changes

## Acceptance

- `parse("2 heaping tablespoons tomato paste")` → name: "tomato paste", unit: "tbsp", qty: 2
- `parse("1 rounded teaspoon baking soda")` → name: "baking soda", unit: "tsp", qty: 1
- `parse("3 packed cups brown sugar")` → name: "brown sugar", unit: "cup", qty: 3
- Existing 267 tests still pass
