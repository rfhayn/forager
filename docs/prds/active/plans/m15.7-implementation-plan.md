# M15.7: Dark Mode, Accessibility & Final QA

## Context

M15.7 is the quality assurance and accessibility phase — the final pass before M15 is complete. It verifies dark mode correctness (including glass effects), adds VoiceOver support, audits Dynamic Type scaling, guards animations with Reduce Motion, replaces `StandardEmptyStateView` with branded `ContentUnavailableView`, and profiles performance. No new layout or features — only verification, accessibility, and polish.

**Depends on**: All prior phases complete — M15.1 (foundation), M15.2 (tokens), M15.3 (grocery UX + animations + haptics), M15.4 (recipes UX), M15.5 (meal plans + ingredients UX), M15.5b (Settings/Categories/Household redesign), M15.6 (glass effects + app icon).

**What changes**: Empty states (StandardEmptyStateView → ContentUnavailableView), accessibility labels/hints on all interactive elements, Reduce Motion guards on all spring/slide animations, dark mode fixes from walkthrough, performance optimizations if needed.

**What does NOT change**: Layout, data model, service layer, glass effects (those are final from M15.6).

**Key PRD references**: §4.5.3 Reduce Motion, §5.5 Empty States, §5.6 Progress Ring accessibility, §5.8 Tap Targets.

## Sub-Phase E: Reduce Motion Audit (1 hour)

### E.1: Animations inventory from M15.3–M15.5

| Animation | File | Type | Guard Strategy |
|-----------|------|------|---------------|
| Progress ring arc | ForagerProgressRing.swift | `.animation(.easeInOut(duration: 0.3))` | Replace with instant (no animation) |
| Bottom progress bar width | GroceryListDetailView.swift | `.animation(.easeInOut(duration: 0.3))` | Replace with instant |
| Category collapse chevron | GroceryListDetailView.swift | `withAnimation(.spring(response: 0.3, dampingFraction: 0.8))` | Replace with instant toggle |
| Check-off sequence | GroceryListDetailView.swift | `withAnimation(.spring(response: 0.3, dampingFraction: 0.7))` | Replace with 0.15s crossfade |
| Checkbox scale effect | GroceryListDetailView.swift | `.animation(.spring(...))` | Remove scale, keep opacity |
| Item checked styling | GroceryListDetailView.swift | `.animation(.easeInOut(duration: 0.3))` | Instant |
| Celebration banner | GroceryListDetailView.swift | `withAnimation { showCelebration }` | Instant appear, keep haptic |
| Filter pill selection | RecipeListView.swift | `withAnimation { activeFilter = }` | Instant |
| Scale pill selection | RecipeListView.swift | `withAnimation { scaleFactor = }` | Instant |
| Category filter selection | IngredientsView.swift | `withAnimation { selectedCategory = }` | Instant |
| Review step navigation | IngredientsView.swift | `withAnimation { currentIndex += 1 }` | Instant |

### E.2: Implementation pattern

Use `@Environment(\.accessibilityReduceMotion)` to guard animations:

```swift
@Environment(\.accessibilityReduceMotion) var reduceMotion

// Pattern 1: withAnimation guard
if reduceMotion {
    item.isCompleted.toggle()
} else {
    withAnimation(.spring(response: 0.3, dampingFraction: 0.7)) {
        item.isCompleted.toggle()
    }
}

// Pattern 2: .animation() modifier guard
.animation(reduceMotion ? nil : .easeInOut(duration: 0.3), value: progress)

// Pattern 3: Scale/bounce effects
.scaleEffect(reduceMotion ? 1.0 : (item.isCompleted ? 1.1 : 1.0))
```

### E.3: Create `withReducedMotion` helper

To avoid repetitive conditionals, add a helper to ForagerTheme:

```swift
extension ForagerTheme {
    /// Returns the appropriate animation for the current Reduce Motion setting
    static func animation(_ animation: Animation, reduceMotion: Bool) -> Animation? {
        reduceMotion ? nil : animation
    }

    /// Standard reduced motion crossfade (0.15s)
    static func reducedMotionCrossfade() -> Animation {
        .easeInOut(duration: 0.15)
    }
}
```

**Usage**:
```swift
withAnimation(reduceMotion ? .easeInOut(duration: 0.15) : .spring(response: 0.3, dampingFraction: 0.7)) {
    item.isCompleted.toggle()
}
```

### E.4: Haptics preserved

Per PRD §4.5.3: "Keep haptic feedback (not visual motion)." All `UIImpactFeedbackGenerator` and `UINotificationFeedbackGenerator` calls remain active regardless of Reduce Motion setting. Haptics are tactile, not visual.

## Sub-Phase F: Glass Contrast & WCAG Verification (1 hour)

### F.1: Text contrast through glass

Glass material adds a translucent overlay that reduces text contrast. Verify all text over glass elements meets WCAG AA:

| Element | Text | Background | Min Ratio | Check |
|---------|------|-----------|-----------|-------|
| Glass card title | `textPrimary` (#2C2418) | Glass over cream | ≥4.5:1 | Measure effective contrast |
| Glass card subtitle | `textSecondary` (#6B5E4F) | Glass over cream | ≥4.5:1 | Secondary text most at risk |
| Glass card caption | `textTertiary` (#8A7B6B) | Glass over cream | ≥3:1 (UI component) | May fail — verify |
| Prominent glass hero text | `textPrimary` | Prominent glass over cream | ≥4.5:1 | Prominent is more opaque |
| Dark mode glass text | `textPrimary` dark (#F5F0E8) | Glass over `#1C1A14` | ≥4.5:1 | |
| Button text on glass | Various | `.buttonStyle(.glass)` | ≥4.5:1 | System glass handles this |
| Category chips through glass | Category colors | Glass over cream | ≥3:1 | Chips are small — risk |

### F.2: Contrast testing methodology

1. Use Xcode Accessibility Inspector → Color Contrast tool
2. Capture screenshots at each glass element
3. Measure effective contrast ratio of text over the rendered glass composite

If any text fails:
- **Option A**: Increase text color weight (e.g., `textTertiary` → `textSecondary`)
- **Option B**: Add `.background(ForagerTheme.surfacePrimary.opacity(0.8))` behind text to boost contrast
- **Option C**: Reduce glass prominence on that element

### F.3: Border contrast in dark mode

| Border | Token | Dark Value | Adjacent Surface | Target Ratio |

| Category collapse/expand | 60fps | Section content appearing/disappearing |
| Tab switching | Instant | No lag between tab renders |
| Push navigation (list → detail) | Smooth | Glass navigation bar transition |

### G.2: Glass rendering performance

Glass effects are GPU-composited, but multiple overlapping glass elements can spike GPU usage:

1. **GroceryListDetailView**: If 10+ category sections each have glass, consider limiting glass to the most prominent elements
2. **RecipeListView**: Glass on every card in a long list — verify LazyVStack dequeues glass views efficiently
3. **MealPlanDetailView day strip**: 7 glass cards in horizontal scroll — should be fine (small count)

### G.3: Memory profiling

Check for:
- Glass effect views retaining large textures
- Animation state leaks from rapid check-off toggling
- `@FetchRequest` triggering unnecessary re-renders on glass views

### G.4: Optimization strategies (if needed)

If performance issues found:
- **Reduce glass elements**: Apply glass only to top-level cards, not nested elements
- **Simplify glass**: Use `.glassEffect(.regular)` instead of `.glassEffect(.prominent)` where possible
- **Remove glass from lists**: Keep shadow-based `.foragerCard()` for list items, glass for hero/prominent elements only
- **Lazy rendering**: Ensure all lists use `LazyVStack` not `VStack`

## Risk Analysis

| Risk | Severity | Mitigation |
|------|----------|------------|
| VoiceOver labels wrong or incomplete | Medium | Test with VoiceOver enabled during development, not just after |
| Dynamic Type AX5 breaks layouts | Medium | Focus on AX3 (most common large size). AX5 is extreme — allow graceful degradation |
| Glass + dark contrast fails WCAG | High | F.1 dedicated contrast verification. Adjust glass prominence or add background tint |
