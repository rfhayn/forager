## Problem Statement

Recipe websites frequently list multiple ingredients on a single line:

| Recipe says | Problem | Should be |
|------------|---------|-----------|
| "1/2 tbsp garlic powder and onion powder" | Creates one template "garlic powder and onion powder" | Two items: "1/2 tbsp garlic powder" + "1/2 tbsp onion powder" |
| "salt and pepper to taste" | Creates one template "salt and pepper" | Two items: "salt" + "pepper" |
| "2 tbsp soy sauce or fish sauce" | Creates one template with alternatives | Two items: "2 tbsp soy sauce" + "2 tbsp fish sauce" (user picks) |
| "juice of 1 lemon and 1 lime" | Creates one combined template | Two items: "1 lemon" + "1 lime" |

This pollutes the ingredient template library with compound entries and prevents proper grocery list aggregation. "Garlic powder" from one recipe won't merge with "garlic powder and onion powder" from another.

## Solution: Import Preview Splitting

Split detection and resolution happens during import preview, before save. The user confirms splits, maintaining control. By save time, all ingredients are clean single items.

### Phase 1: Local Auto-Detection (1h)

Add a heuristic detector that flags likely multi-ingredient lines in the import preview.

**Detection patterns:**
- `" and "` between two ingredient-like words (not prep phrases)
- `" or "` suggesting alternatives
- Multiple comma-separated ingredients without quantities

**Known compound exclusions (do NOT split):**
- "salt and pepper", "oil and vinegar", "bread and butter"
- "macaroni and cheese", "peanut butter and jelly"
- Prep phrases: "peeled and deveined", "washed and dried", "seeded and diced"

**UI:** Subtle split icon badge on detected lines (similar to the confidence dot indicator).

**Implementation:** New function in `IngredientParsingService`:
```swift
static func detectMultiIngredient(_ text: String) -> Bool
```

No LLM call needed for detection — fast local regex.

### Phase 2: LLM Split Function (1h)

New function in `ClaudeIngredientParser`:
```swift
func splitMultiIngredient(_ line: String) async throws -> [String]?
```

**Separate prompt** (not the batch parser):
```
Given this ingredient line, determine if it contains multiple distinct ingredients.
If yes, return each as a separate complete ingredient string with appropriate quantities.
If no (single ingredient with modifiers), return null.

Rules:
- Distribute shared quantities: "1/2 tbsp garlic powder and onion powder"
  becomes ["1/2 tbsp garlic powder", "1/2 tbsp onion powder"]
- Handle alternatives: "soy sauce or fish sauce" becomes both with same quantity
- Handle "X and Y to taste" → ["X", "Y"] (strip "to taste")
- Do NOT split prep descriptions: "peeled and deveined shrimp" is ONE ingredient
- Do NOT split compound foods: "macaroni and cheese" is ONE ingredient
```

Returns `nil` for single ingredients, `[String]` for splits.

### Phase 3: Preview UI Integration (1h)

In `RecipeImportPreviewView`, add to the existing context menu (line ~689):

```swift
.contextMenu {
    // Existing AI parse button
    if parsingService.isLLMAvailable {
        Button { Task { await singleLLMParse(index: index) } } label: {
            AIParseLabel()
        }
    }

    // NEW: Split multi-ingredient
    if IngredientParsingService.detectMultiIngredient(text) && parsingService.isLLMAvailable {
        Button { Task { await splitIngredient(at: index) } } label: {
            Label("Split Ingredients", systemImage: "square.split.2x1")
        }
    }
}
```

**Split flow:**
1. User long-presses ingredient → context menu shows "Split Ingredients"
2. LLM call returns split results (e.g., ["1/2 tbsp garlic powder", "1/2 tbsp onion powder"])
3. Show confirmation: "Split into 2 ingredients?"
4. On confirm: splice `draft.ingredients.value` array at index
5. Recompute `ingredientMatches` for new indices (shift higher indices by split count - 1)
6. New lines get default match status

**Index remapping:**
```
Before: [item0, item1, "garlic and onion", item3, item4]
After:  [item0, item1, "garlic powder", "onion powder", item3, item4]

ingredientMatches: shift all keys >= index+1 by (splitCount - 1)
categoryAssignments: same shift
```

### Phase 4: Visual Indicator for Detected Lines (0.5h)

Show a subtle badge on lines detected as multi-ingredient by the heuristic (Phase 1):

- Small icon (e.g., "2" badge or split icon) next to the ingredient status dot
- Indicates "this line may contain multiple ingredients"
- Visible even without tapping the context menu
- Disappears after the line is split or edited
