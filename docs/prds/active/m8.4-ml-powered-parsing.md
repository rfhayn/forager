## 1. Problem Statement

Forager's current parsing pipeline — `RegexIngredientParser` (fast path) → `NLPIngredientParser` (Apple NaturalLanguage fallback) → `HybridIngredientParser` (router) — handles standard recipe formats well but fails on:

| Input | Expected | Current Result | Root Cause |
|-------|----------|----------------|------------|
| `3 cloves garlic` | qty=3, unit=clove, name=garlic | name="cloves garlic" | Regex doesn't know "clove" is a unit in this context |
| `1/4 tsp black pepper` (via meal plan) | name=black pepper | name="/ black pepper" | `extractCleanIngredientName()` strips fraction parts separately |
| `bananas` | template=bananas | template=banana | Pluralization table incomplete |
| `milk 2%` | no warning | needsReview=true | Digit heuristic doesn't know about product variants |
| `a handful of fresh cilantro` | qty=1, name=cilantro | name="handful fresh cilantro" | Descriptive amounts not fully extracted |
| `salt and pepper to taste` | name=salt and pepper | name="salt and pepper to taste" | Qualifier stripping incomplete |

These are **class-level failures** — fixing them one-by-one with regex additions creates an ever-growing rule set that's brittle and untestable. A machine-learned model trained on real ingredient data solves the entire class.

## 2. Approach: Dataset-Bootstrapped CoreML Sequence Labeler

### Why Not the Original M8.4 Plan?

The M8.4 plan in the M8 Meta-PRD (lines 1585-2384) proposed a Create ML Text Classifier that:
- Requires **100+ user corrections** before training — cold start problem
- Uses flat classification ("2.0|cup|flour") — loses token-level context
- Can't handle unseen ingredient formats without retraining

### What Changed: Open-Source Dataset Bootstrapping

Two high-quality open-source datasets provide immediate training data:

| Dataset | Size | License | Accuracy | Approach |
|---------|------|---------|----------|----------|
| [strangetom/ingredient-parser](https://github.com/strangetom/ingredient-parser) | 81,000 sentences | MIT | 95.25% sentence / 98.09% word | CRF (pycrfsuite) |
| [NYT ingredient-phrase-tagger](https://github.com/NYTimes/ingredient-phrase-tagger) | 180,000 examples | Apache 2.0 | N/A (CRF baseline) | CRF + manual review |

Combined, these give us **~260,000 labeled ingredient sentences** — enough to train a production-quality model from day one without waiting for user corrections.

### Architecture: Sequence Labeling (BIO Tagging)

Instead of flat classification, use **token-level sequence labeling** (the standard approach in NLP for entity extraction):

```
Input:  "2    cups   all-purpose   flour"
Labels:  B-QTY B-UNIT B-NAME       I-NAME
```

BIO tags:
- `B-QTY` / `I-QTY` — quantity tokens
- `B-UNIT` / `I-UNIT` — unit tokens
- `B-NAME` / `I-NAME` — ingredient name tokens
- `B-COMMENT` / `I-COMMENT` — qualifiers, preparation notes
- `O` — other / separator tokens

This handles any format naturally — the model learns what role each token plays, regardless of ordering.

### On-Device CoreML Pipeline

```
Training (Mac/CI):
  NYT + strangetom CSVs
  → Unified BIO-tagged format
  → PyTorch BiLSTM-CRF or Transformer
  → coremltools conversion
  → .mlpackage (bundled in app)

Runtime (iOS):
  Input text
  → Tokenize
  → CoreML prediction (token labels)
  → Decode BIO tags → ParserResult
  → Slot into HybridIngredientParser
```

**Privacy**: All inference on-device. Training data is open-source. No user data ever leaves the device.

The parser protocol (`IngredientParser`) and routing architecture (`HybridIngredientParser`) were designed for extensibility at M8.3. Adding the ML parser requires changes to exactly 3 files:

### 3.1 New File: `Services/Parsing/MLIngredientParser.swift`

Implements `IngredientParser` protocol. Loads CoreML model, tokenizes input, runs inference, decodes BIO tags into `ParserResult`.

### 3.2 Modified: `Services/Parsing/HybridIngredientParser.swift`

Current routing (62 lines):
```
regex → if confidence ≥ 0.8, return → else NLP → return higher
```

New routing:
```
regex → if confidence ≥ 0.9, return
      → else ML → if confidence ≥ 0.8, return
      → else NLP → return highest of all three
```

The ML parser sits between regex (microseconds, free) and NLP (milliseconds, Apple framework). Only consulted when regex isn't highly confident.

### 3.3 Modified: `Services/Parsing/IngredientParser.swift`

No protocol changes needed. `ParserResult` already has `parserUsed: String` — the ML parser will tag results as `"ml"`.

### 3.4 Existing: Telemetry Integration

`ParsingTelemetryService` already logs `parserUsed` per event (M8.3, schema v2). ML parser results will automatically flow into telemetry with `parserUsed: "ml"` — no changes needed.

### Phase 2: Model Architecture & Training (4-5h)

**Deliverable**: Trained PyTorch model with ≥95% token accuracy on test set

**Architecture choice**: BiLSTM-CRF

Why BiLSTM-CRF over Transformer:
- **Model size**: ~2-5 MB vs. 50-100 MB for a transformer — critical for app bundle size
- **Inference speed**: <5ms vs. 20-50ms — must stay under parsing target (<50ms)
- **Training data**: 260k sentences is enough for BiLSTM-CRF but marginal for a transformer
- **CoreML conversion**: Well-supported path via coremltools

**Model specification**:
```python
# tools/ml-training/train_model.py
class IngredientTagger(nn.Module):
    embedding_dim = 128     # Character + word embeddings
    hidden_dim = 256        # BiLSTM hidden size
    num_labels = 9          # B-QTY, I-QTY, B-UNIT, I-UNIT, B-NAME, I-NAME,
                            # B-COMMENT, I-COMMENT, O
    vocab_size = ~8000      # Word vocabulary from training data
    char_vocab = 128        # ASCII character vocabulary
```

**Training script** (`tools/ml-training/train_model.py`):
1. Load prepared datasets
2. Build word + character vocabularies
3. Train BiLSTM-CRF with:
   - Learning rate: 0.001 (Adam)
   - Batch size: 64
   - Max epochs: 30 with early stopping (patience=5)
   - Dropout: 0.5
4. Evaluate on test set
5. Export model checkpoint

**Acceptance criteria**:
- Token-level accuracy ≥ 96% on test set
- Sentence-level accuracy ≥ 92% on test set
- Model file < 10 MB
- Training completes in < 2 hours on MacBook Pro

### Phase 4: MLIngredientParser Implementation (3-4h)

**Deliverable**: `Services/Parsing/MLIngredientParser.swift` passing all tests

**File**: `Services/Parsing/MLIngredientParser.swift`

```swift
import Foundation
import CoreML

class MLIngredientParser: IngredientParser {
    let parserName = "ml"

    private let model: IngredientTagger  // Auto-generated by Xcode
    private let vocabulary: [String: Int]

    init?() {
        // Load model — fail gracefully if model not available
        guard let model = try? IngredientTagger(configuration: .init()) else {
            return nil
        }
        self.model = model
        self.vocabulary = Self.loadVocabulary()
    }

    func parse(_ input: String) -> ParserResult {
        let tokens = tokenize(input)
        let tokenIds = tokens.map { vocabulary[$0.lowercased()] ?? 0 }

        // Run CoreML inference
        guard let prediction = try? model.prediction(token_ids: ...) else {
            return fallbackResult(input)
        }

        // Decode BIO tags into structured components
        let components = decodeBIOTags(tokens: tokens, tagIds: prediction.tag_ids)

        return ParserResult(
            name: components.name,
            quantity: components.quantity,
            unit: components.unit,
            notes: components.comment,
            confidence: components.confidence,
            originalText: input,
            parserUsed: parserName
        )
    }
}
```

Key implementation details:
- **Tokenization**: Split on whitespace, handle punctuation, Unicode fractions → decimal
- **Vocabulary lookup**: Map tokens to integer IDs using vocab from training
- **BIO decoding**: Concatenate consecutive I-tags with their B-tag, handle edge cases
- **Confidence**: Derived from model's per-token softmax probabilities (geometric mean)
- **Graceful fallback**: If model fails to load → `init?()` returns nil → HybridIngredientParser skips ML step

**Acceptance criteria**:
- Implements `IngredientParser` protocol
- Handles all 7 regex pattern categories (unicode fractions, ranges, parentheticals, compounds, standard, qualifiers, descriptive)
- Returns correct `parserUsed: "ml"` for telemetry
- Gracefully returns nil from init if model unavailable
- All tokens decoded — no lost information

### Phase 5: HybridIngredientParser Integration (2h)

**Deliverable**: Updated routing with ML parser in the chain

**File**: `Services/Parsing/HybridIngredientParser.swift`

Change from:
```swift
private let regexParser = RegexIngredientParser()
private let nlpParser = NLPIngredientParser()
```

To:
```swift
private let regexParser = RegexIngredientParser()
private let mlParser: MLIngredientParser?  // nil if model unavailable
private let nlpParser = NLPIngredientParser()

init() {
    self.mlParser = MLIngredientParser()
}
```

New routing logic:
```swift
func parse(_ input: String) -> ParserResult {
    // Step 1: Regex fast path (microseconds)
    let regexResult = regexParser.parse(input)
    if regexResult.confidence >= 0.9 { return regexResult }

    // Step 2: ML model (milliseconds)
    if let mlParser = mlParser {
        let mlResult = mlParser.parse(input)
        if mlResult.confidence >= 0.8 { return mlResult }

        // Step 3: NLP fallback only if ML also uncertain
        if regexResult.confidence < 0.5 && mlResult.confidence < 0.5 {
            let nlpResult = nlpParser.parse(input)
            return [regexResult, mlResult, nlpResult]
                .max(by: { $0.confidence < $1.confidence })!
        }

        // Return better of regex vs ML
        return mlResult.confidence > regexResult.confidence ? mlResult : regexResult
    }

    // Fallback: original behavior (no ML model available)
    if regexResult.confidence >= 0.8 { return regexResult }
    let nlpResult = nlpParser.parse(input)
    return nlpResult.confidence > regexResult.confidence ? nlpResult : regexResult
}
```

**Key design decisions**:
- Regex threshold raised from 0.8 → 0.9 (only skip ML for very high-confidence regex)
- ML parser is optional (`MLIngredientParser?`) — app works without model
- NLP only consulted when both regex and ML are uncertain
- `parserUsed` telemetry tracks which parser won

**Acceptance criteria**:
- Existing tests pass unchanged (regex-dominated inputs still work)
- ML parser consulted for ambiguous inputs
- App still works if model file is removed from bundle
- Telemetry correctly tracks "regex", "ml", "nlp", "hybrid" attribution

## 8. Risks and Mitigations

| Risk | Impact | Mitigation |
|------|--------|------------|
| CoreML model too large for app bundle | App size bloat | BiLSTM-CRF targets 2-5 MB; quantize to float16 if needed |
| Model accuracy lower than regex for standard formats | Regression | Regex still handles high-confidence inputs (≥0.9); ML only consulted for ambiguous cases |
| coremltools conversion fails for CRF layer | Blocks Phase 3 | CRF can be replaced with simple argmax + post-processing in Swift; or use ONNX → CoreML path |
| NYT dataset quality issues | Poor training | strangetom dataset is cleaner (95% accuracy); use it as primary, NYT as supplement |
| Training requires GPU | Developer bottleneck | BiLSTM-CRF trains on CPU in <2h for this dataset size; no GPU required |
| Python tooling dependency | Setup complexity | Minimal deps (torch, coremltools, numpy, pandas); documented in requirements.txt |
