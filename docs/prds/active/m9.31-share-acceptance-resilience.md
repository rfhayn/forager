# M9.31: CKShare Acceptance Resilience — Prevent Ghost Detection During Sync

**Status**: ⏳ PLANNED
**Estimated**: 2-3 hours (4 fixes)
**Priority**: CRITICAL (destroys household for all participants)
**Depends On**: M9.30 (security hardening)
**Last Updated**: March 22, 2026

---

## Problem Statement

When a third person (Joe) accepted a household invitation via public link, the CKShare on the owner's (Rich's) device was temporarily unresolvable during CloudKit's mirroring delegate import. `isCurrentUserParticipant()` returned `false`, ghost detection fired, and **deleted the household entity — destroying the household for all participants**.

### Timeline (from logs)
1. **21:32:29** — Owner's household working fine (2 participants, CKShare valid)
2. **~21:32:35** — Joe accepts share URL → CloudKit modifies CKShare on server → pushes to owner
3. **21:32:41** — Owner's `fetchShares(matching:)` returns empty (mirroring delegate mid-import)
4. **21:32:41-21:33:29** — Rapid-fire `noShareRecord` errors as sync events re-trigger departure checks
5. **21:33:40** — Owner force-quit and relaunched → `isCurrentUserParticipant` returned `false` → ghost detection deleted the household → deletion synced to CloudKit → household destroyed for everyone

### Root Cause

In `isCurrentUserParticipant()` (HouseholdService.swift line ~2664):
```swift
} catch HouseholdError.noShareRecord {
    if household.objectID.persistentStore == privateStore {
        return true  // assumes owner (CloudKit migration pending)
    }
    return false  // ← TREATS TRANSIENT FAILURE AS PERMANENT
}
```

Once the Household moves to the shared store (after `container.share()`), ANY `fetchShares` failure returns `false`. Combined with ghost detection in `loadCurrentHousehold()` that deletes on `false`, a single transient CloudKit failure destroys the household.

---

## Solution: 4 Layered Fixes

### Fix 1: Never Ghost-Detect the Owner's Household (CRITICAL)

The owner should NEVER have their own household deleted by ghost detection. Before the ghost deletion code in `loadCurrentHousehold()`, check if the current user is the owner:

```swift
// In loadCurrentHousehold(), before ghost deletion (line ~351):
if let ownerRecordName = household.ownerRecordName {
    let currentRecordName = try? await getCurrentUserRecordName()
    if currentRecordName == ownerRecordName {
        // Owner's fetchShares failed transiently — load anyway, do NOT delete
        currentHousehold = household
        DiagnosticLogger.shared.warning(
            "M9.31: Owner's getShare failed but household is ours — loading anyway",
            category: .household)
        return
    }
}
```

**Why**: The owner created the household. Their `ownerRecordName` matches their iCloud identity. A transient `fetchShares` failure doesn't change ownership. Load the household and let CloudKit recover.

### Fix 2: Retry `fetchShares` Before Concluding Non-Participant (CRITICAL)

In `isCurrentUserParticipant()`, when `getShare()` throws `noShareRecord` for a shared-store household, retry once after 2 seconds:

```swift
} catch HouseholdError.noShareRecord {
    let privateStore = PersistenceController.shared.privateStore
    if household.objectID.persistentStore == privateStore {
        // M9.30: Check left/deleted flag
        if let id = household.id?.uuidString, hasLeftHousehold(id) { return false }
        return true
    }
    // M9.31: Retry once — fetchShares may be mid-import from sync
    try? await Task.sleep(nanoseconds: 2_000_000_000)
    do {
        let retryShare = try await getShare(for: household)
        return retryShare.currentUserParticipant != nil
    } catch {
        return false  // genuinely not a participant after retry
    }
}
```

**Why**: `NSPersistentCloudKitContainer.fetchShares(matching:)` can transiently return empty during mirroring delegate imports triggered by remote changes. A 2-second retry covers the typical import duration.

### Fix 3: Require Data Check Before Ghost Deletion (Defense in Depth)

A true ghost household from a failed `createHouseholdAndShare()` is **empty** — the create-empty-then-copy pattern ensures no data exists until after sharing succeeds. A household with real data (recipes, lists, categories) is never a ghost:

```swift
// Before ghost deletion:
let hasData = (household.recipes?.count ?? 0) > 0
    || (household.weeklyLists?.count ?? 0) > 0
    || (household.categories?.count ?? 0) > 0
if hasData {
    // Household has real data — this is NOT a ghost, fetchShares just failed
    currentHousehold = household
    DiagnosticLogger.shared.warning(
        "M9.31: Household has \(household.recipes?.count ?? 0) recipes — not a ghost, loading anyway",
        category: .household)
    return
}
```

**Why**: Ghost households are always empty. A household with recipes and lists that fails a share lookup is experiencing a transient sync issue, not a ghost.

### Fix 4: Debounce Ghost Detection Across Launches (Defense in Depth)

Don't ghost-delete on the first failure. Track consecutive failures in UserDefaults. Only delete if the household has failed `isCurrentUserParticipant` across **3 consecutive app launches**:

```swift
// In loadCurrentHousehold(), ghost detection path:
let ghostKey = "ghostDetectionCount_\(household.id?.uuidString ?? "")"
let consecutiveFailures = UserDefaults.standard.integer(forKey: ghostKey)
if consecutiveFailures < 3 {
    UserDefaults.standard.set(consecutiveFailures + 1, forKey: ghostKey)
    currentHousehold = household  // Load it anyway, give CloudKit time to recover
    DiagnosticLogger.shared.warning(
        "M9.31: Ghost detection attempt \(consecutiveFailures + 1)/3 — loading anyway",
        category: .household)
    return
}
// 3+ consecutive failures — genuinely a ghost, delete it
UserDefaults.standard.removeObject(forKey: ghostKey)
```

Reset the counter when `isCurrentUserParticipant` succeeds:
```swift
if isMember {
    // Clear any ghost detection counter
    if let id = household.id?.uuidString {
        UserDefaults.standard.removeObject(forKey: "ghostDetectionCount_\(id)")
    }
    currentHousehold = household
    // ... rest of success path
}
```
