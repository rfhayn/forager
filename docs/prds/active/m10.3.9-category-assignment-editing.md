## S1 Overview

### 1.1 Problem Statement

When a user imports a recipe, uncategorized ingredients trigger the `CategoryAssignmentModal`. Currently, the user can only:
- Pick a category from a list
- Skip (leave as "Uncategorized")

There's no way to **edit the ingredient name** (to fix OCR/extraction errors) or get a **category suggestion** based on existing data. The user must manually pick a category for every new ingredient, even though the app already has data that could inform predictions.

### 1.2 Solution

Enhance `CategoryAssignmentModal` with:
1. **Inline ingredient editing** — tap to edit the ingredient name, rerun parsing + template matching on save
2. **Category prediction** — suggest a category based on existing template data (same-word heuristic, then LLM in M10.6)
3. **Auto-assign on match** — if the edited name matches an existing categorized template, auto-fill the category

### 1.3 Design Principles

- **Edit is optional** — the current assign/skip flow remains the default path
- **Predictions are suggestions** — user can always override
- **Shared component** — `CategoryAssignmentModal` is used by both import and grocery list flows; changes must work for both
- **LLM-ready** — the prediction hook will be enhanced by M10.6 Claude API integration

## S3 Implementation

### Phase 1: Inline Editing (2h)

Add an edit mode to `IngredientAssignmentRow` so the user can correct ingredient names.

**Changes to `IngredientAssignmentRow`:**
- Add `@State private var isEditing = false`
- Add `@State private var editText: String` (initialized from `template.name`)
- Tap pencil icon → show `TextField` replacing the name label
- On commit (return key or "Done"):
  1. Parse edited text: `parsingService.parseIngredient(text: editText)` → get clean `displayName`
  2. Search for existing template: `templateService.searchTemplates(query: displayName, limit: 5)`
  3. If exact match found with category → auto-assign category, update UI
  4. If exact match found without category → still uncategorized, but name is corrected
  5. If no match → new name, update template via `templateService.updateTemplate()`
  6. Exit edit mode

**New callback on `IngredientAssignmentRow`:**
```swift
let onIngredientEdited: (IngredientTemplate, String, String?) -> Void
// Parameters: template, newName, autoMatchedCategory (nil if no match)
```

**Parent (`CategoryAssignmentModal`) handles:**
- Updating template name via `ingredientTemplateService.updateTemplate()`
- Auto-filling `categoryAssignments[templateID]` if a category was matched
- Re-rendering the row with updated name and status

**Environment objects needed in row:**
- `IngredientParsingService` (for `parseIngredient`)
- `IngredientTemplateService` (for `searchTemplates`)
- Both already injected at app root via `@EnvironmentObject`

### Phase 2: Category Prediction (1.5h)

Add a heuristic category suggestion for ingredients that don't match existing templates.

**Prediction strategy (pre-LLM):**

1. **Word-overlap heuristic**: Search all categorized templates, find ones sharing significant words with the new ingredient. If multiple templates in the same category share words → suggest that category.
   - Example: "garlic powder" → existing "onion powder" (Spices), "chili powder" (Spices) → suggest "Spices"
   - Ignore common words: "fresh", "dried", "ground", "large", "small", "whole"

2. **Suffix matching**: Common ingredient suffixes map to categories:
   - `*powder`, `*seasoning`, `*spice` → Spices
   - `*sauce`, `*paste`, `*oil`, `*vinegar` → Condiments
   - `*cheese`, `*cream`, `*milk`, `*butter`, `*yogurt` → Dairy
   - `*flour`, `*sugar`, `*starch` → Baking

3. **Confidence**: If heuristic has ≥2 supporting templates in the same category, show as suggestion. Otherwise, no prediction.

**New method on `IngredientTemplateService`:**
```swift
func predictCategory(for ingredientName: String) -> (category: String, confidence: Float)?
```

**UI in `IngredientAssignmentRow`:**
- When prediction available: show "Suggested: [Category]" chip below the name with accept/reject
- Accept → auto-assign
- Reject → open category picker (existing flow)
- When no prediction: show "Choose Category" (existing flow)

### Phase 3: Integration & Polish (1h)

- Wire prediction into initial `CategoryAssignmentModal` load (not just after edits)
- All newly created templates get prediction checked on modal appear
- Summary bar: "N auto-suggested · N need review"
- Ensure both import and grocery list flows work correctly
- Test with templates that have varied category coverage

**LLM enhancement hook (M10.6):**
- `predictCategory()` will gain an optional LLM path:
  ```
  predictCategory(for:) → heuristic prediction
  predictCategoryWithLLM(for:) → Claude API call (batch all unknowns)
  ```
- The UI already handles suggestions — M10.6 just improves prediction quality

## S5 Data Flow

### Edit → Reparse → Match
```
User taps ✏ on "garlik powdr"
  → TextField shows, user corrects to "garlic powder"
  → User taps Done
  │
  ├─ parseIngredient("garlic powder") → displayName: "Garlic Powder"
  ├─ searchTemplates("Garlic Powder", limit: 5)
  │   ├─ MATCH FOUND (existing template with category "Spices")
  │   │   → Auto-assign "Spices" to categoryAssignments[id]
  │   │   → Show ✓ Spices in row
  │   │
  │   └─ NO MATCH
  │       ├─ predictCategory("Garlic Powder")
  │       │   ├─ PREDICTION: "Spices" (confidence: 0.8)
  │       │   │   → Show "Suggested: Spices" chip
  │       │   │
  │       │   └─ NO PREDICTION
  │       │       → Show "Choose Category" (existing flow)
  │       │
  │       └─ updateTemplate(template, name: "Garlic Powder", ...)
  │
  └─ Exit edit mode
```

## S7 Risks and Mitigations

| Risk | Impact | Mitigation |
|------|--------|------------|
| Edit changes template shared by other recipes | Could rename a template used elsewhere | Only rename if template is new (usageCount ≤ 1) or create new template |
| Category prediction is wrong | User assigns wrong category | Predictions are suggestions with explicit accept; override always available |
| CategoryAssignmentModal is shared (import + grocery) | Changes could break grocery flow | Test both paths; edit feature uses optional callback |
| Template merge on name match | Two templates could point to same ingredient | Check before update; if match found, reassign ingredient to existing template |
