## Problem Statement

A 50-recipe stress test across 9 recipe sources (AllRecipes, BudgetBytes, DamnDelicious, SimplyRecipes, Skinnytaste, RecipeTinEats, LoveAndLemons, FoodNetwork) found ~300 parsing issues across 575 ingredients. Top bug categories:

| Bug | Occurrences | Impact |
|-----|-------------|--------|
| P0: Word-splitting ("egg" → "eg g") | 10+ | CRITICAL — corrupts template library |
| P1: Prep in names ("garlic, minced") | ~285 | HIGH — 50% of all issues |
| P2: Site-specific junk (prices, notes) | ~65 | MEDIUM — 2 sites affected |
| P3: Orphan fragments ("crumbled") | 5+ | LOW — missing ingredient names |
| P4: Space-before-punctuation | 4+ | LOW — cosmetic |
| P5: Fraction-to-decimal | 1 | LOW — display only |
| P6: Quantity ranges ("2 or 3 tbsp") | 5+ | LOW — range left in name |

## Industry Research

Compared against open-source parsers (NYT ingredient-phrase-tagger, strangetom/ingredient-parser at 94.7% accuracy) and commercial apps (Paprika, AnyList, Whisk, Mealime, Yummly, Zestful API). Key findings:

- **Forager's 3-tier hybrid (regex → ML → NLP) is more sophisticated than most** — no open-source project does confidence-based routing
- **BiLSTM-CRF is the right on-device tradeoff** — transformers achieve 95.9% F1 but are too heavy for CoreML
- **Industry consensus**: prep instructions belong in a separate field, not the ingredient name
- **Best-in-class preprocessing** (strangetom library): trailing period stripping on units, footnote/reference stripping, "(optional)" as structured boolean
- **Compound disambiguation** (Zestful): distinguishes product names ("ground cinnamon") from prep ("diced celery") using a product knowledge base — aspirational for future ML training data

## Solution: 4-Phase Pipeline Fix

### Phase 1: Centralized Pre-Processing (2-3h)

**New file: `Services/Parsing/IngredientPreprocessor.swift`**

Stateless utility called from `HybridIngredientParser.parse()` (line 47) so all three parser tiers benefit. Steps in order:

1. **Strip price annotations**: `\(\$[\d.]+\)` and standalone `\$\d+\.?\d*` (Budget Bytes)
2. **Strip double-paren notes**: `\(\([^)]*\)\)` (RecipeTinEats "((Note 1))")
3. **Strip footnote references**: `\[\d+\]`, `\*+$`, `\(see note[s]?\)`, `\(Note \d+\)` (industry best practice)
4. **Fix leading comma in parens**: `\(,\s*` → `(` (RecipeTinEats "(, minced)")
5. **Unicode fraction → slash fraction**: `⅔` → `2/3`, `½` → `1/2`, etc. (prevents word-split decomposition AND repeating decimal bug)
6. **Strip trailing period on units**: "1 tsp." → "1 tsp", "2 tbsp." → "2 tbsp" (industry standard per strangetom)
7. **Fix space-before-punctuation**: `\s+,` → `,` and letter + `\s+-` → letter + `-`
8. **Normalize whitespace**: collapse multiple spaces, trim, normalize Unicode spaces (U+00A0, U+200B, U+FEFF)

**Files:**
- CREATE `Services/Parsing/IngredientPreprocessor.swift`
- MODIFY `Services/Parsing/HybridIngredientParser.swift` line 47

### Phase 2: Word-Splitting Fix (2-3h)

**Root cause:** `MLIngredientParser.assembleResult()` (lines 107-143) joins tokens with spaces. NFKD normalization + diacritic stripping in the tokenizer can split Unicode characters across token boundaries. BIO tagging can also isolate the last character.

**Fix:** Merge single-character orphan tokens back into preceding word in `assembleResult()`:
```swift
var merged: [String] = []
for token in nameTokens {
    if token.count == 1, let last = merged.last, last.count > 1 {
        merged[merged.count - 1] = last + token
    } else { merged.append(token) }
}
let name = merged.joined(separator: " ")
```

Handles: "eg"+"g" → "egg", "lemo"+"n" → "lemon", "jalape"+"ño" → "jalapeño", "avocad"+"o" → "avocado"

**Files:**
- MODIFY `Services/Parsing/MLIngredientParser.swift` lines 107-143

### Phase 3: Prep Instruction Improvements (3-5h)

**3A: Expand prepKeywords** (`RegexIngredientParser.swift` lines 156-164)

Add ~25 missing phrases to the `extractParentheticalPrep()` keyword set:
- Serving context: "for garnish", "for serving", "for dusting", "for dipping", "for topping"
- Quantity modifiers: "plus more to taste", "plus more for serving", "plus more for garnish", "or more to taste", "or to taste"
- Conditional: "if needed", "if desired", "as needed"
- Portioning: "divided", "separated"
- Multi-word prep: "peeled and deveined", "cored and sliced", "seeded and diced", "stemmed and seeded"
- Cut styles: "cut into cubes", "cut into strips", "cut into wedges", "cut into pieces", "cut into chunks"
- Temperature: "at room temp", "room temp"

**3B: Convert comma-qualifier to procedural** (`RegexIngredientParser.swift` line 662)

Replace single-word regex with procedural approach:
1. Split at first comma
2. Check right side against `knownPrepWords` set (first word signals prep)
3. `knownPrepWords`: "minced", "diced", "chopped", "sliced", "crushed", "grated", "shredded", "julienned", "peeled", "seeded", "trimmed", "halved", "quartered", "torn", "roughly", "finely", "thinly", "coarsely", "lightly", "freshly", "cut"

This catches multi-word preps: "finely minced", "peeled and deveined", "cut into bite-size pieces", "freshly ground".

**3C: Orphan fragment detection** (add to `IngredientPreprocessor.swift`)

`isOrphanFragment()` detects lines that are ONLY prep text ("crumbled", "seeds removed, very thinly sliced") with no recognizable ingredient name. Call from `SchemaRecipeMapper.filterIngredientHeaders()` to filter before parsing.

**3D: "(optional)" as structured data** (industry best practice)

When "(optional)" is detected and stripped, set a flag on the parse result that can flow through to the UI. Currently just moves to notes — enhance to set `isOptional: Bool` on `ParserResult`. Display as a subtle badge on the import preview.

**Files:**
- MODIFY `Services/Parsing/RegexIngredientParser.swift` lines 156-164 (prepKeywords), line 662 (comma-qualifier)
- ADD to `Services/Parsing/IngredientPreprocessor.swift` (orphan detection)
- MODIFY `Services/Import/SchemaRecipeMapper.swift` line 163 (orphan filtering)
- MODIFY `Services/Parsing/ParserResult.swift` or equivalent (add isOptional field)

### Phase 4: Edge Cases (1-2h)

**4A: "X or Y" quantity ranges**

Add regex for "2 or 3 tablespoons" alongside existing "3 to 4 cups" pattern. Also add word-range-no-unit: "6 to 8 carrots" → take the higher value, store range as metadata (industry convention: use higher value for shopping).

**4B: Post-name quantity patterns** (industry insight from strangetom)

Handle "chicken breast, 2 lbs, diced" where quantity appears AFTER the ingredient name instead of before. Detect with pattern: `name, \d+ unit, prep`. Not common but occurs in some recipe formats.

**4C: "Salt and pepper"** — leave as-is (working as designed, in compoundIngredients exclusion set).

**Files:**
- MODIFY `Services/Parsing/RegexIngredientParser.swift` around line 311
