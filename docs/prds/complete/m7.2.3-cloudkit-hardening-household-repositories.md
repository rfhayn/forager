## 🏛️ Architectural Principles

### **Core Principle 1: Household as Aggregate Root**

**Definition**: All collaborative data is reachable from `Household` via Core Data relationships.

**Implementation** (Phase 0):
```swift
entity Household {
    // Existing
    name: String
    ownerID: String
    members: [HouseholdMember]
    
    // NEW (Phase 0)
    weeklyLists: [WeeklyList]           // Cascade delete
    recipes: [Recipe]                   // Nullify (personal library)
    mealPlans: [MealPlan]               // Cascade delete
    categories: [Category]              // Nullify (shared vocab)
    ingredientTemplates: [IngredientTemplate]  // Nullify (shared vocab)
}
```

### **Core Principle 2: No Cross-Store Relationships**

**Rule**: Private objects cannot relate to shared objects, and vice versa.

**Enforcement** (Phase 6):
```swift
#if DEBUG
extension NSManagedObjectContext {
    func validateNoCrossStoreRelationships() {
        // Checks all inserted/updated objects
        // Fatal error if relationship crosses stores
        // See Phase 6 for complete implementation
    }
}
#endif
```

### **Core Principle 3: Explicit Scope**

**Rule**: Every data operation has explicit scope via `DataScope` enum.

**Implementation** (Phase 2 - Gemini):
```swift
enum DataScope {
    case personal
    case household(id: NSManagedObjectID, store: NSPersistentStore)
}

// Usage
let scope = scopeProvider.activeScope
switch scope {
case .personal:
    // Create in private store, household = nil
case .household(let householdID, let store):
    // Create in shared store, auto-set household relationship
}
```

### **Core Principle 4: Store-Scoped Repositories**

**Rule**: Repositories fetch from explicit stores, not unified queries.

**Implementation** (Phase 5):
```swift
// ✅ Explicit store scoping
func fetchHouseholdRecipes(household: Household) -> [Recipe] {
    let request = Recipe.fetchRequest()
    request.predicate = NSPredicate(format: "household == %@", household)
    request.affectedStores = [sharedStore]  // Explicit!
    return try context.fetch(request)
}
```

### **Core Principle 5: HouseholdScoped Invariant**

**Rule**: Any entity conforming to `HouseholdScoped` MUST:
- Be created exclusively via `ManagedObjectFactory`
- Have `household != nil` when in household scope  
- Have `household == nil` when in personal scope
- Never transition between scopes after creation (except via attach-then-share migration)

**Why**: Scope is not mutable business state. Moving objects between households after creation is explicitly unsupported. This constraint:
- Prevents cross-store relationship violations
- Makes ownership clear and deterministic
- Simplifies debugging (object's store never changes post-creation except during share)

**Enforcement**:
- ManagedObjectFactory is the ONLY creation path for household-scoped entities
- Cross-store validator catches violations in DEBUG
- Protocol conformance makes it compiler-enforced

**Source**: Gemini feedback - "Make household-scoped a first-class invariant"

---

### **Architectural Constraint: One Active Scope**

**Rule**: The application operates in one active data scope at a time (personal or household). Cross-scope editing in a single screen is intentionally unsupported.

**What This Means**:
- At any given moment, `ScopeProvider.activeScope` returns `.personal` OR `.household`, not both
- All views show data from ONE scope (personal OR household)
- Users switch scope by creating/joining/leaving household (not via UI toggle)

**What This Prevents** (Future Feature Creep):
- ❌ "Show personal + household recipes in one list"
- ❌ "Drag personal list into household"
- ❌ "Copy recipe from personal to household" (use attach-then-share)
- ❌ "Multi-household picker in same view"

**Why**: Cross-scope editing is solvable later (M8+), but costly if introduced accidentally. This constraint:
- Keeps Phase 2-6 implementation simple
- Makes ownership clear to users
- Prevents UX confusion ("Why can't I edit this?")
- Reduces bug surface (no mixed-scope predicates)

**Future**: Multi-household support (M9+) will add household switcher, but still maintains "one active scope" invariant.

**Source**: Gemini feedback - "Explicitly document one active scope at a time"

```swift
extension NSManagedObject {

              let coordinator = context.persistentStoreCoordinator else {
            print("⚠️ [\(label)] \(type(of: self)): No context/coordinator")

        print("\n📦 [\(label)] Pending store assignments:")
```

Recipes are treated as content with potential personal value. Unlike weekly lists and meal plans (which are ephemeral and household-specific), recipes represent curated content that users may want to:
- Export for personal use
- Copy out of household before leaving
- Reuse in future households or personal scope

Therefore, recipes are not cascade-deleted with the household. If a household is deleted:
- Recipes remain in the database (relationship nullified)
- User can manually delete unwanted recipes
- Or implement "Export to Personal Library" in future (M8+)

This design preserves user investment in recipe curation while maintaining the workspace model for truly household-owned data (lists, meal plans).

```swift
// DataScope.swift
import CoreData

/// Represents the ownership scope for data in the app
enum DataScope {
    /// Data belongs to the current user only (Private Store)
    case personal
    
    /// Data belongs to a household (Shared Store)
    /// - Parameters:
    ///   - id: NSManagedObjectID of the Household (prevents stale references)
    ///   - store: The persistent store where household currently resides
    case household(id: NSManagedObjectID, store: NSPersistentStore)
}

/// Protocol for entities that can be scoped to a household
protocol HouseholdScoped: NSManagedObject {
    var household: Household? { get set }
    var householdKey: String? { get set }  // For unique constraints
}

// MARK: - HouseholdScoped Conformance

extension WeeklyList: HouseholdScoped {}
extension Recipe: HouseholdScoped {}
extension MealPlan: HouseholdScoped {}
extension Category: HouseholdScoped {}
extension IngredientTemplate: HouseholdScoped {}
```

#### **2.2: ScopeProvider Implementation** (1.5h)

**File**: `Services/Persistence/HouseholdScopeProvider.swift` (NEW)

```swift
// HouseholdScopeProvider.swift
import CoreData

/// Provides the current data scope based on household state
class HouseholdScopeProvider {
    private let householdService: HouseholdService
    private let persistence: PersistenceController
    
    init(householdService: HouseholdService, persistence: PersistenceController) {
        self.householdService = householdService
        self.persistence = persistence
    }
    
    /// Returns the active data scope
    /// - Personal: No household OR household not shared
    /// - Household: Household exists and is shared
    var activeScope: DataScope {
        // 1. Check if a household is currently active
        guard let household = householdService.currentHousehold else {
            return .personal
        }
        
        // 2. Identify which store contains this household record
        // Critical: Household moves from Private → Shared during share creation
        guard let coordinator = persistence.container.persistentStoreCoordinator,
              let householdStore = coordinator.persistentStore(for: household.objectID) else {
            return .personal
        }
        
        // 3. Return household scope with stable ObjectID reference
        return .household(id: household.objectID, store: householdStore)
    }
}
```

**Key Points** (Gemini):
- Uses `persistentStore(for:)` to **resolve** which store household is in
- Prevents stale references by using `NSManagedObjectID`
- Automatically handles household moving during share creation

#### **2.3: ManagedObjectFactory** (1.5h)

**File**: `Services/Persistence/ManagedObjectFactory.swift` (NEW)

```swift
// ManagedObjectFactory.swift
import CoreData

/// Factory for creating managed objects with automatic store assignment
/// and household relationship management
final class ManagedObjectFactory {
    private let context: NSManagedObjectContext
    private let scopeProvider: HouseholdScopeProvider
    private let persistence: PersistenceController
    
    init(context: NSManagedObjectContext, 
         scopeProvider: HouseholdScopeProvider, 
         persistence: PersistenceController) {
        self.context = context
        self.scopeProvider = scopeProvider
        self.persistence = persistence
    }
    
    /// Creates a new object in the appropriate store based on current scope
    /// - Parameters:
    ///   - type: The NSManagedObject type to create
    ///   - configure: Configuration closure for setting properties
    /// - Returns: The created object (already assigned to correct store)
    func make<T: NSManagedObject>(_ type: T.Type, configure: (T) -> Void) -> T {
        let object = T(context: context)
        let scope = scopeProvider.activeScope
        
        #if DEBUG
        print("🏭 ManagedObjectFactory: Creating \(type)")
        #endif
        
        switch scope {
        case .personal:
            // Assign to private store
            context.assign(object, to: persistence.privateStore)
            
            // Explicitly ensure household relationship is nil
            if let scopedObject = object as? HouseholdScoped {
                scopedObject.household = nil
                scopedObject.householdKey = nil
            }
            
            #if DEBUG
            print("   Scope: Personal (Private Store)")
            #endif
            
        case .household(let householdID, let targetStore):
            // 1. Assign to the store where household lives
            context.assign(object, to: targetStore)
            
            // 2. Set household relationship
            if let scopedObject = object as? HouseholdScoped {
                // Fetch household in current context (prevents stale references)
                if let household = try? context.existingObject(with: householdID) as? Household {
                    scopedObject.household = household
                    scopedObject.householdKey = household.id?.uuidString
                } else {
                    print("⚠️ ManagedObjectFactory: Could not resolve household from ObjectID")
                }
            }
            
            #if DEBUG
            print("   Scope: Household (Store: \(targetStore.url?.lastPathComponent ?? "unknown"))")
            #endif
        }
        
        configure(object)
        
        #if DEBUG
        object.logStoreIdentity("  Factory Result")
        #endif
        
        return object
    }
}
```

**Key Points** (Gemini):
- **Personal case**: Explicitly sets `household = nil` (prevents cross-store violations)
- **Household case**: Uses `existingObject(with:)` (prevents stale references)
- **Auto-sets householdKey**: For unique constraints and faster predicates

```swift
// HouseholdService.swift

func createHouseholdAndShare(name: String, moveExistingData: Bool) async throws {
    let context = persistence.container.viewContext
    
    // 1. Create Household in Private Store
    let household = Household(context: context)
    household.id = UUID()
    household.name = name
    household.ownerID = try await getCurrentUserID()
    context.assign(household, to: persistence.privateStore)
    
    #if DEBUG
    print("\n🏗️ M7.2.3 Phase 4: Creating household and share")
    print("   Household: \(name)")
    print("   Owner: \(household.ownerID)")
    print("   Move existing data: \(moveExistingData)")
    #endif
    
    // 2. The "Attach" Logic: Set relationships while still in Private
    if moveExistingData {
        #if DEBUG
        print("📎 Attaching existing data to household...")
        #endif
        
        // Attach recipes (TIGHTENED: Only personal recipes)
        let recipeRequest = Recipe.fetchRequest()
        recipeRequest.predicate = NSPredicate(format: "household == nil")  // Personal only
        recipeRequest.affectedStores = [persistence.privateStore]  // Explicit store
        let recipes = try context.fetch(recipeRequest)
        household.addToRecipes(NSSet(array: recipes))
        #if DEBUG
        print("   Attached \(recipes.count) personal recipes")
        #endif
        
        // Attach weekly lists (TIGHTENED: Only personal lists)
        let listRequest = WeeklyList.fetchRequest()
        listRequest.predicate = NSPredicate(format: "household == nil")
        listRequest.affectedStores = [persistence.privateStore]
        let lists = try context.fetch(listRequest)
        household.addToWeeklyLists(NSSet(array: lists))
        #if DEBUG
        print("   Attached \(lists.count) personal lists")
        #endif
        
        // Attach meal plans (TIGHTENED: Only personal plans)
        let mealPlanRequest = MealPlan.fetchRequest()
        mealPlanRequest.predicate = NSPredicate(format: "household == nil")
        mealPlanRequest.affectedStores = [persistence.privateStore]
        let mealPlans = try context.fetch(mealPlanRequest)
        household.addToMealPlans(NSSet(array: mealPlans))
        #if DEBUG
        print("   Attached \(mealPlans.count) personal meal plans")
        #endif
        
        // Categories and templates handled by deduplicator after sync
    }
    
    // 3. Create owner member (will move with household)
    let member = HouseholdMember(context: context)
    member.id = UUID()
    member.household = household
    member.email = household.ownerID
    member.displayName = extractDisplayName(from: household.ownerID)
    member.role = "owner"
    member.status = "active"
    member.joinedDate = Date()
    context.assign(member, to: persistence.privateStore)  // Will move with household
    
    #if DEBUG
    print("👤 Created owner member: \(member.displayName ?? "Unknown")")
    #endif
    
    // 4. Save to ensure graph is in Private SQLite file
    try context.save()
    #if DEBUG
    print("💾 Saved household + attachments to Private Store")
    household.logStoreIdentity("   Household")
    member.logStoreIdentity("   Owner Member")
    #endif
    
    // 5. Share the Aggregate Root (CloudKit moves entire graph!)
    #if DEBUG
    print("☁️ Creating CloudKit share...")
    #endif
    
    // CRITICAL: Use `to: nil` - Core Data creates CKShare internally
    try await persistence.container.share([household], to: nil)
    
    #if DEBUG
    print("✅ Share created! CloudKit moved household + graph to Shared Zone")
    #endif
    
    // 6. Post-share refresh (objects moved stores)
    context.refreshAllObjects()  // ← Gemini's simplification!
    
    #if DEBUG
    print("🔄 Refreshed all objects from Shared Store")
    household.logStoreIdentity("   Household (post-refresh)")
    member.logStoreIdentity("   Owner Member (post-refresh)")
    if moveExistingData {
        if let firstRecipe = household.recipes.first {
            firstRecipe.logStoreIdentity("   Sample Recipe (post-refresh)")
        }
    }
    
    // 🔒 VALIDATE: Share completed successfully
    if let refreshedHousehold = try? context.existingObject(with: household.objectID) as? Household {
        let scope = HouseholdScopeProvider(
            householdService: self,
            persistence: persistence
        ).activeScope
        
        switch scope {
        case .household:
            print("✅ Share validation PASSED: currentHousehold in household scope")
        case .personal:
            assertionFailure("""
            ⚠️ Share validation FAILED: Household still in personal scope!
            
            This indicates share creation failed or partial completion.
            Check CloudKit Dashboard for share record.
            """)
        }
    } else {
        print("⚠️ Could not validate share - household object not found")
    }
    
    print("🎉 M7.2.3 Phase 4: Household creation complete!\n")
    #endif
    
    // 7. Update service state
    self.currentHousehold = household
}
```

```swift
#if DEBUG
extension NSManagedObjectContext {
    /// Validates that all related objects belong to the same persistent store
    /// Call before save() during development to catch cross-store violations
    func validateNoCrossStoreRelationships() {
        let insertedOrUpdated = insertedObjects.union(updatedObjects)
        
        for object in insertedOrUpdated {
            guard let coordinator = persistentStoreCoordinator,
                  let currentStore = coordinator.persistentStore(for: object.objectID) else {
                continue
            }
            
            // Inspect all relationships for this entity
            for (name, relationship) in object.entity.relationshipsByName {
                // Simplified: Check To-One relationships (covers most cases)
                guard !relationship.isToMany else { continue }
                
                if let relatedObject = object.value(forKey: name) as? NSManagedObject,
                   let relatedStore = coordinator.persistentStore(for: relatedObject.objectID) {
                    
                    // VIOLATION: Related object in different store!
                    if currentStore.identifier != relatedStore.identifier {
                        fatalError("""
                        
                        ❌ CROSS-STORE RELATIONSHIP VIOLATION DETECTED
                        
                        Object: \(object.entity.name ?? "Unknown")
                        ObjectID: \(object.objectID.uriRepresentation())
                        Store: \(currentStore.url?.lastPathComponent ?? "Unknown") (\(currentStore.identifier))
                        
                        Relationship: \(name)
                        
                        Related Object: \(relatedObject.entity.name ?? "Unknown")
                        ObjectID: \(relatedObject.objectID.uriRepresentation())
                        Store: \(relatedStore.url?.lastPathComponent ?? "Unknown") (\(relatedStore.identifier))
                        
                        This is a programming error. All related objects must be in the same persistent store.
                        Check ManagedObjectFactory for incorrect store assignment.
                        
                        """)
                    }
                }
            }
        }
    }
}
#endif
```
