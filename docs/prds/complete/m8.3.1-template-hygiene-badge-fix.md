## Problem Statement

Manual testing of the M8.3 Hybrid NLP Parser revealed two integration issues that prevent the parser from delivering its intended value to users:

### Issue 1: Ingredient Templates Store Full Text Instead of Names

**Observed behavior**: The Ingredients tab — which serves as the user's ingredient library — displays entries like "½ Cup Sour Cream", "Two Cloves Garlic", and "¼ Tsp Cayenne". These include quantities and units that don't belong in a name-only library.

**Expected behavior**: The Ingredients tab should show only ingredient names: "sour cream", "garlic", "cayenne". Quantities and units belong on recipes and grocery lists, not in the ingredient template library.

**User impact**: The ingredient library loses its value as a reusable name catalog. Users can't build a clean library of ingredients to select from when creating recipes and grocery lists. Duplicate templates proliferate ("garlic" vs "Two Cloves Garlic" vs "2-3 Cloves Garlic").

**Root cause**: 5 of 8 code paths that create `IngredientTemplate` objects bypass the centralized `findOrCreateTemplate()` method. These paths create templates directly without normalization, without setting `canonicalName` (breaking deduplication), and without stripping quantity/unit information. The M8.3 parser correctly extracts ingredient names (verified by 62 passing unit tests), but the views don't consistently use the parser output through the normalized path.

**Affected code paths (direct template creation)**:
| Location | Template Name Source |
|----------|---------------------|
| `CreateRecipeView.saveRecipe()` | `parsed.name` — correct value, but no normalization or dedup |
| `EditRecipeView.saveRecipe()` | `parsed.name` — same issue |
| `AddListItemView.saveToTemplates()` | `parsed.name` — same issue |
| `GroceryListDetailView.saveToTemplates()` | `parsed.name` — same issue |
| `AddIngredientsToListView` | `extractCleanIngredientName()` — custom stripping, no normalization |

**Correct code paths (through `findOrCreateTemplate`)**:
| Location | Notes |
|----------|-------|
| `IngredientParsingService.parseAndConnectIngredients()` | Full normalization + canonicalName + dedup |
| `MealPlanDetailView` | Uses `findOrCreateTemplate` |
| `RecipeListView.addIngredientsWithParsing()` | Uses `findOrCreateTemplate` |

### Issue 2: Yellow Confidence Badge Not Visible

**Observed behavior**: No yellow exclamation badge appears in the recipe ingredient list, even for ingredients that the parser handles with low confidence (e.g., "a pinch of saffron", "salt to taste", "a handful of parsley").

**Expected behavior**: Ingredients parsed with reduced confidence should show a yellow badge so users know these may need review.

**User impact**: Users have no visual signal that some ingredients were parsed with uncertainty. They can't identify which ingredients might need manual correction.

**Root cause**: The badge threshold is `parseConfidence < 0.5`, which was appropriate for the pre-M8.3 parser that returned 0.0 for unparseable inputs. With M8.3's enhanced patterns:
- Descriptive amounts ("a pinch of saffron") → confidence 0.60
- Qualifiers ("salt to taste") → confidence 0.70
- NLP fallback results → confidence 0.30-0.75

All of these now parse above 0.5, making the badge effectively invisible for the patterns M8.3 was designed to handle. The improved accuracy is correct, but the badge threshold wasn't recalibrated.

---

## Solution

### Fix 1: Consolidate Template Creation Through `findOrCreateTemplate`

Replace all 5 direct `IngredientTemplate(context:)` creations with calls to the existing `IngredientTemplateService.findOrCreateTemplate(name:category:)`. This method already:
- Applies 4-phase normalization (case, plural, abbreviation, variation)
- Sets `canonicalName` for semantic deduplication
- Checks for existing templates before creating new ones
- Routes through `HouseholdIngredientTemplateRepository` for household-aware uniqueness

**Files to modify**:
- `forager/CreateRecipeView.swift` — `saveRecipe()`
- `forager/EditRecipeView.swift` — `saveRecipe()`
- `forager/AddListItemView.swift` — `saveToTemplates()`
- `forager/GroceryListDetailView.swift` — `saveToTemplates()`
- `forager/AddIngredientsToListView.swift` — template creation block

### Fix 2: Recalibrate Confidence Badge Threshold

Raise the yellow badge threshold from `< 0.5` to `< 0.7` in both recipe and grocery list views. This aligns the badge with M8.3's confidence tiers:

| Confidence | Badge | Meaning |
|------------|-------|---------|
| >= 0.7 | None | Reliable parse (standard, unicode fractions, ranges with units) |
| 0.5 - 0.69 | Yellow | Reduced confidence (descriptive amounts, compound phrases without units) |
| < 0.5 | Yellow | Low confidence (NLP fallback, name-only, unparseable) |

**Files to modify**:
- `forager/RecipeListView.swift` — `ingredientRowView`
- `forager/GroceryListDetailView.swift` — equivalent badge logic

### Fix 3: Update Test Recipe Data

Add a truly-unparseable ingredient to the test recipes to ensure the badge is always visible during manual testing. Current M8.3 patterns handle most natural language inputs — we need an edge case that genuinely fails.

**File to modify**: `forager/RecipeListView.swift` — `createAllTestRecipes()`
