## Problem Statement

When users add the same ingredient to a grocery list from multiple recipes, the quantities should be aggregated automatically. Currently, the system uses **string concatenation** (e.g., `"8 oz + 12 oz"`) and defers numeric merging to a manual "Consolidate" button that the user must discover and click.

**Current behavior**: Add 8oz chicken broth from Recipe A, then 12oz from Recipe B → grocery list shows `"8.0 oz + 12.0 oz chicken broth"`. User must find and click the merge button to get `"20 oz chicken broth"`.

**Expected behavior**: Add 8oz chicken broth from Recipe A, then 12oz from Recipe B → grocery list immediately shows `"20 oz chicken broth"` tagged with both Recipe A and Recipe B as sources.

**User impact**: The string-concatenated quantities are confusing and require an extra step to resolve. The consolidation button is an implementation detail leaking into the UX — users shouldn't need to know about a merge step.

## Solution

### Change 1: Extract Merge Logic into `GroceryMergeService`

Create a new testable service that encapsulates all quantity merging logic. The service is **pure computation** — no Core Data, no view context. It takes value-type inputs and returns value-type outputs, making it fully unit-testable.

**New file**: `Services/GroceryMergeService.swift`

```swift
/// Input describing one side of a merge (existing item or incoming ingredient)
struct GroceryMergeInput {
    let numericValue: Double
    let standardUnit: String?
    let isParseable: Bool
    let parseConfidence: Double
}

/// Output of a merge operation
struct GroceryMergeResult {
    let numericValue: Double
    let standardUnit: String?
    let displayText: String
    let parseConfidence: Double
    let didMergeQuantity: Bool  // false when unparseable, zero, or incompatible
}

class GroceryMergeService {
    private let conversionService: UnitConversionService

    init(conversionService: UnitConversionService = UnitConversionService()) {
        self.conversionService = conversionService
    }

    /// Merge an incoming ingredient quantity into an existing grocery list item.
    /// Returns the merged result — caller applies it to the Core Data object.
    func merge(existing: GroceryMergeInput, incoming: GroceryMergeInput) -> GroceryMergeResult

    /// Format a numeric value + unit into user-facing display text.
    /// Examples: (20, "oz") → "20 oz", (1.5, "cup") → "1.5 cups", (3, nil) → "3"
    func formatDisplayText(value: Double, unit: String?) -> String
}
```

**Merge rules** (implemented inside `merge()`):

1. **Both parseable, same unit**: Add quantities directly
2. **Both parseable, convertible units**: Convert incoming to existing's unit via `UnitConversionService`, then add
3. **Both parseable, incompatible units**: Don't merge quantities (`didMergeQuantity = false`)
4. **Parseable + unparseable**: Keep existing quantity unchanged (`didMergeQuantity = false`)
5. **Unparseable + unparseable**: No quantity change (`didMergeQuantity = false`)
6. **Either has zero quantity**: No quantity change (`didMergeQuantity = false`)
7. **Confidence**: Always `min(existing, incoming)` regardless of merge outcome

### Change 2: Wire Service into AddIngredientsToListView

Replace the string concatenation in `addToShoppingList()` with a call to `GroceryMergeService.merge()`.

**File**: `forager/AddIngredientsToListView.swift`
**Function**: `addToShoppingList(targetList:)` (line ~421)

The view creates a `GroceryMergeService` (like it already creates `RecipeScalingService`), builds `GroceryMergeInput` structs from the existing `GroceryListItem` and the incoming `Ingredient`, calls `merge()`, and applies the `GroceryMergeResult` back to the Core Data object:

```swift
if let existingItem = findExistingItem(named: cleanName, in: existingItems) {
    let existing = GroceryMergeInput(
        numericValue: existingItem.numericValue,
        standardUnit: existingItem.standardUnit,
        isParseable: existingItem.isParseable,
        parseConfidence: existingItem.parseConfidence
    )
    let incoming = GroceryMergeInput(
        numericValue: ingredient.isParseable ? ingredient.numericValue * scaleFactor : 0,
        standardUnit: ingredient.standardUnit,
        isParseable: ingredient.isParseable,
        parseConfidence: ingredient.parseConfidence
    )
    let result = mergeService.merge(existing: existing, incoming: incoming)

    existingItem.numericValue = result.numericValue
    existingItem.parseConfidence = result.parseConfidence
    if result.didMergeQuantity {
        existingItem.displayText = result.displayText
        existingItem.standardUnit = result.standardUnit
    }
    existingItem.addToSourceRecipes(recipe)
}
```

### Change 4: Confidence Tracking During Merges

The yellow confidence badge (M8.3.1: `parseConfidence < 0.7`) is preserved on the grocery list. When two items merge, the resulting confidence must reflect the **least certain** source so users can still spot items that may need review.

**Rule: Merged confidence = min(existing, new)**

Examples:
| Existing Item | New Item | Merged Confidence | Badge? |
|---------------|----------|-------------------|--------|
| "2 cups chicken broth" (0.95) | "1.5 cups chicken broth" (0.95) | 0.95 | No |
| "2 cups chicken broth" (0.95) | "chicken broth to taste" (0.70) | 0.70 | Borderline (at threshold) |
| "2 cups chicken broth" (0.95) | "a splash of chicken broth" (0.60) | 0.60 | Yes |
| "salt to taste" (0.70) | "salt to taste" (0.70) | 0.70 | Borderline |

Implementation — add to the merge block in `addToShoppingList()`:
```swift
// Confidence: always take the minimum so uncertainty surfaces to the user
existingItem.parseConfidence = min(existingItem.parseConfidence, ingredient.parseConfidence)
```

### Change 5: Handle Edge Cases

When merging quantities at add-time, handle these edge cases:

- **Parseable + parseable (same unit)**: Add quantities, take min confidence, rebuild displayText.
- **Parseable + parseable (convertible units)**: Convert via `UnitConversionService`, add, take min confidence, rebuild displayText.
- **Parseable + unparseable**: Keep the existing item's numeric values unchanged. Downgrade `parseConfidence` to `min(existing, new)` so the yellow badge surfaces the ambiguity. Add the recipe source. Do NOT attempt numeric merge — the unparseable side has no reliable quantity.
- **Unparseable + unparseable**: No numeric merge. Take min confidence. Add recipe source only.
- **Different unit categories** (e.g., "2 cups" + "3 cloves"): This shouldn't happen for the same ingredient, but if it does, keep the existing item's values, take min confidence, and add the recipe source.
- **Zero quantities** (e.g., "salt to taste"): Keep existing display, take min confidence, add recipe source only.

## Success Criteria

1. Adding the same ingredient from two recipes produces a single grocery list entry with summed quantity
2. Source recipes are tracked on the merged item
3. No consolidation button visible in the grocery list toolbar
4. Unit conversion works for compatible units (cups/tbsp/tsp, lbs/oz)
5. **Yellow badge** (`parseConfidence < 0.7`) visible on grocery list items where any source ingredient had low confidence — merging never hides uncertainty from the user
6. Merging a parseable item with an unparseable item preserves existing quantity and downgrades confidence to show the badge
7. Zero regressions — all existing tests pass, build succeeds
