# M10.6.16: Build 16 Bug Fixes — Category Display + Modal Height

**Status**: COMPLETE
**Branch**: `main` (hotfix on main)
**Created**: March 4, 2026

## Problem

Device testing of build 16 (M10.6.15) revealed two bugs:

1. **Categories show "Choose Category"** on saved recipe detail view despite being correctly set during import. Root cause: `computeIngredientMatches()` re-parses ingredient text locally, producing different names than the AI parser (e.g., "chopped green onion" vs "green onion"). Template lookup fails even though the ingredient has a direct Core Data relationship to the correct template with category.
2. **Category picker modal** at `.medium` detent doesn't show all 7 categories without scrolling; no drag indicator to hint at expansion.

## Fixes

| Fix | Scope | Files |
|-----|-------|-------|
| 1 | Use ingredient's linked template category as fallback in recipe detail | RecipeListView.swift |
| 2a | Add drag indicator to category picker in recipe detail | RecipeListView.swift |
| 2b | Add drag indicator to category picker in import preview | RecipeImportPreviewView.swift |

## Verification

- Build: SUCCEEDED
- Fix 1: Same "positive signal preservation" pattern as M10.6.15 Fix 1
- Fix 2: Consistent with EditRecipeView which already has `.presentationDragIndicator(.visible)`
