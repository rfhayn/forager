## §1 Overview

### 1.1 Problem Statement

The deterministic ingredient parsing pipeline (regex → ML → NLP) achieves 92-94% quantity extraction on structured recipe data. However, ~7-8% of imported ingredient lines contain patterns no regex or BiLSTM model can handle:

- **Messy prose**: `"Grating Nutmeg"` → `{name: "Nutmeg", notes: "grating"}`
- **Inverted structures**: `"Juice of 1 Lemon"` → `{qty: 1, name: "Lemon", notes: "juice of"}`
- **Multi-ingredient**: `"salt and pepper to taste"` → could split into 2 items
- **"X to serve" semantics**: `"Sugar to serve"` → `{name: "Sugar", notes: "to serve"}`

These are **semantic** gaps — they require natural language understanding that regex pattern matching cannot provide. The M10.5 spike validated this by showing that after 12 pipeline fixes, the remaining 25 gaps in a 100-recipe corpus are all semantic in nature.

### 1.2 Solution

Add an **optional** Claude API integration for recipe import ingredient parsing. When enabled, the Claude API parses all ingredient lines in a single batch API call before the recipe is saved, with silent fallback to the deterministic pipeline on any failure.

### 1.3 Design Principles

- **App is fully functional without it** — toggle OFF by default, no nudges, no setup banners
- **Claude-only for M10.6** — validate the pattern before adding GPT/Gemini (M10.7+)
- **User owns their API key** — stored in iOS Keychain, no server-side proxy
- **Silent fallback** — user never sees a parsing failure; all errors fall back to the pipeline
- **Zero schema changes** — no Core Data model version bump, no migration
- **Existing tests untouched** — all 267+ tests pass without modification

## §2 Architecture

### 2.1 Integration Workflow

The recipe import flow has 2 stages:
1. **Extraction** (async): Extractors pull recipe apart from HTML/text → `ImportDraftRecipe` with raw ingredient strings
2. **Parsing** (sync, in `saveImport`): Each string → `HybridIngredientParser.parse()` → structured data

The LLM targets **stage 2 (parsing)**, not extraction. It acts as a **bypass** of the existing pipeline — not a 4th tier within it.

**With LLM, the save flow becomes**:
```
User taps "Save" on import preview
  │
  ▼
saveImport(from: draft) — becomes async
  │
  ├─ LLM enabled + configured?
  │   YES → Send ALL ingredient strings to Claude in ONE batch API call
  │         → tool_use structured output → [LLMParserResult]
  │         → Map via toParserResult() → create Ingredient entities
  │         → DONE (pipeline skipped entirely)
  │
  │   ANY failure (401, 429, network, malformed, timeout)
  │         → Silent fallback ↓
  │
  └─ NO (or fallback) → Existing pipeline (unchanged):
      parseAndConnectIngredients()
        → regex (≥0.9) → ML (≥0.8) → NLP fallback
        → create Ingredient entities
```

### 2.2 What Stays the Same

- **Extraction** (step 1) is untouched — JSON-LD, WKWebView, FM, Heuristic extractors
- **3 existing parsers** (regex, ML, NLP) are untouched
- **`IngredientParsingService` API** is untouched — only `RecipeImportService` changes
- **Manual recipe entry** still uses the pipeline (no LLM for per-keystroke parsing)
- **All 267+ existing tests** pass without modification

### 2.3 New Protocol: LLMIngredientParser

```swift
/// Protocol for LLM-based ingredient parsing with provider abstraction.
/// Separate from IngredientParser because: (1) async vs sync, (2) batch vs per-line,
/// (3) network dependency vs local-only. Mixing would break 3 conformers + 267+ tests.
protocol LLMIngredientParser {
    /// Parse a batch of ingredient lines in a single API call.
    /// Categories array allows AI to assign grocery categories alongside parsing.
    func parseBatch(_ lines: [String], categories: [String]) async throws -> [LLMParserResult]

    /// Provider identifier for telemetry ("claude", "gpt", "gemini")
    var providerName: String { get }

    /// Check if this provider is configured and available
    var isConfigured: Bool { get }
}
```

**Why a separate protocol** (not extending `IngredientParser`):
- `IngredientParser.parse()` is **synchronous** + **per-line** — 3 existing conformers depend on this
- `LLMIngredientParser.parseBatch()` is **async** + **batch** — fundamentally different API shape
- Forcing `IngredientParser` to be async would cascade through `HybridIngredientParser`, `IngredientParsingService`, and all 11+ call sites
- The LLM parser lives at the `RecipeImportService` level, not inside the hybrid router

### 2.4 LLMParserResult

```swift
/// Result type from LLM parsing, bridges to existing ParserResult
struct LLMParserResult {
    let name: String
    let quantity: Double?
    let unit: String?
    let notes: String?
    let confidence: Float  // 0.95 for successful LLM parse (confidence is binary)
    var category: String?  // AI-assigned grocery category (M10.6.8)

    /// Bridge to existing ParserResult used by Ingredient entity creation
    func toParserResult(originalText: String, provider: String) -> ParserResult {
        ParserResult(
            name: name,
            quantity: quantity,
            unit: unit,
            notes: notes,
            confidence: confidence,
            originalText: originalText,
            parserUsed: provider  // "claude"
        )
    }
}
```

## §3 API Design

### 3.1 Request Format

```
POST https://api.anthropic.com/v1/messages
Headers:
  x-api-key: {user's API key}
  anthropic-version: 2023-06-01
  content-type: application/json
```

### 3.2 System Prompt

```
You are an ingredient parser for a grocery/recipe app. Parse each ingredient line
into structured components. Be precise with quantities and units.

Rules:
- Extract quantity as a decimal number (e.g., "1/2" → 0.5, "2 1/2" → 2.5)
- Standardize common abbreviations: tablespoon/tbsp/tbs → "tbsp",
  teaspoon/tsp → "tsp", ounce/oz → "oz", pound/lb → "lb"
- Keep metric units as-is: g, kg, ml, L
- Separate preparation notes from the ingredient name
  (e.g., "2 cups flour, sifted" → name: "flour", notes: "sifted")
- Count items (2 eggs) have quantity but null unit
- Bare names (salt, pepper) have null quantity and null unit
- "X to taste/to serve" → quantity null, notes: "to taste"/"to serve"
- Preserve the original ingredient name casing
- Do NOT convert between unit systems (keep grams as grams, cups as cups)
- If a line contains multiple ingredients ("salt and pepper"), split into separate items
```

### 3.3 Tool Definition

```json
{
  "name": "parse_ingredients",
  "description": "Parse ingredient lines into structured components",
  "input_schema": {
    "type": "object",
    "properties": {
      "ingredients": {
        "type": "array",
        "items": {
          "type": "object",
          "properties": {
            "name": { "type": "string", "description": "Ingredient name" },
            "quantity": { "type": ["number", "null"], "description": "Numeric quantity or null" },
            "unit": { "type": ["string", "null"], "description": "Unit of measurement or null" },
            "notes": { "type": ["string", "null"], "description": "Preparation notes or null" }
          },
          "required": ["name"]
        }
      }
    },
    "required": ["ingredients"]
  }
}
```

### 3.4 User Message Format

```
Parse these ingredient lines:
1. 400g mushrooms
2. 2 cups flour, sifted
3. salt and pepper to taste
4. Juice of 1 Lemon
5. Grating Nutmeg
```

Lines are numbered so the model maintains order. Multi-ingredient splits (line 3 → 2 results) are allowed — the response array may be longer than the input array.

### 3.5 Retry Strategy

| Error | Retry? | Backoff | Max Attempts |
|-------|--------|---------|--------------|
| 429 (rate limited) | Yes | 1s, 2s, 4s exponential | 3 |
| 529 (overloaded) | Yes | 1s, 2s, 4s exponential | 3 |
| 401 (invalid key) | No | — | 1 (show error in Settings) |
| 5xx (server error) | No | — | 1 (silent fallback) |
| Network error | No | — | 1 (silent fallback) |
| Timeout (15s) | No | — | 1 (silent fallback) |

### 3.6 Response Validation

Before accepting LLM results, validate:
1. Response contains `tool_use` content block with `parse_ingredients` tool
2. Decoded `ingredients` array is non-empty
3. Every item has a non-empty `name` field
4. Quantities are positive when present (reject negatives or zero)
5. No single ingredient name exceeds 250 characters (validation limit)

On any validation failure → silent fallback to pipeline.

| Metric | Value |
|--------|-------|

| Avg ingredients/recipe | 12-15 |
| Avg input tokens/recipe | ~500 (system + tool + user) |
| Avg output tokens/recipe | ~300 (tool_use response) |
| Cost per recipe | ~$0.0005 |
| Typical monthly usage (5-20 recipes) | $0.0025-$0.01 |
| Heavy usage (50 recipes/month) | ~$0.025 |

## §4 Auth & Key Management

### 4.1 Keychain Extension

Extend existing `KeychainHelper` (`Services/KeychainHelper.swift`) with LLM-specific methods:

```swift
extension KeychainHelper {
    private static let llmKeyPrefix = "llm_api_key_"

    /// Save an LLM provider API key to Keychain
    static func saveLLMAPIKey(provider: String, key: String) {
        guard let data = key.data(using: .utf8) else { return }
        write(key: "\(llmKeyPrefix)\(provider)", data: data)
    }

    /// Retrieve an LLM provider API key from Keychain
    static func getLLMAPIKey(provider: String) -> String? {
        guard let data = read(key: "\(llmKeyPrefix)\(provider)") else { return nil }
        return String(data: data, encoding: .utf8)
    }

    /// Delete an LLM provider API key from Keychain
    static func deleteLLMAPIKey(provider: String) {
        let deleteQuery: [String: Any] = [
            kSecClass as String: kSecClassGenericPassword,
            kSecAttrService as String: service,
            kSecAttrAccount as String: "\(llmKeyPrefix)\(provider)"
        ]
        SecItemDelete(deleteQuery as CFDictionary)
    }
}
```

**Note**: `read(key:)` and `write(key:data:)` are already `private static` methods on `KeychainHelper`. The extension needs access to these — either make them `fileprivate` or add the LLM methods directly to the existing `enum KeychainHelper`.

### 4.2 API Key Validation

- Anthropic keys start with `sk-ant-` — validate prefix on paste/entry
- On entry: trim whitespace, check prefix, store if valid
- On invalid prefix: show inline error "Anthropic API keys start with sk-ant-"
- "Test Connection" button makes a minimal API call (`messages` with 1 token max) to verify the key works

### 4.3 Deep Link to Console

Provide a "Get API Key" button that opens:
`https://console.anthropic.com/settings/keys`

This is the direct link to the Anthropic Console API keys page.

## §6 LLMSettingsService

### 6.1 Service Design

**File**: `Services/LLMSettingsService.swift`

```swift
@MainActor
class LLMSettingsService: ObservableObject {
    static let shared = LLMSettingsService()

    // MARK: - Published State

    /// Whether LLM parsing is enabled (UserDefaults, OFF by default)
    @Published var isLLMEnabled: Bool {
        didSet { UserDefaults.standard.set(isLLMEnabled, forKey: "llm_enabled") }
    }

    /// Selected LLM provider ("claude" for M10.6)
    @Published var selectedProvider: String {
        didSet { UserDefaults.standard.set(selectedProvider, forKey: "llm_provider") }
    }

    /// Connection status (in-memory, not persisted)
    @Published var connectionStatus: ConnectionStatus = .notConfigured

    // MARK: - Connection Status

    enum ConnectionStatus {
        case notConfigured
        case testing
        case connected
        case invalid(String)  // Error message
    }

    // MARK: - Init

    private init() {
        self.isLLMEnabled = UserDefaults.standard.bool(forKey: "llm_enabled")
        self.selectedProvider = UserDefaults.standard.string(forKey: "llm_provider") ?? "claude"
        // Check if key exists on init
        if KeychainHelper.getLLMAPIKey(provider: selectedProvider) != nil {
            connectionStatus = .connected  // Assume valid until tested
        }
    }

    // MARK: - API Key Management

    func saveAPIKey(_ key: String) {
        KeychainHelper.saveLLMAPIKey(provider: selectedProvider, key: key)
        connectionStatus = .connected
    }

    func deleteAPIKey() {
        KeychainHelper.deleteLLMAPIKey(provider: selectedProvider)
        connectionStatus = .notConfigured
    }

    func getAPIKey() -> String? {
        KeychainHelper.getLLMAPIKey(provider: selectedProvider)
    }

    // MARK: - Connection Test

    func testConnection() async {
        connectionStatus = .testing
        guard let apiKey = getAPIKey() else {
            connectionStatus = .notConfigured
            return
        }

        let parser = ClaudeIngredientParser(apiKey: apiKey)
        do {
            // Minimal parse call to validate key
            _ = try await parser.parseBatch(["1 cup flour"])
            connectionStatus = .connected
        } catch {
            connectionStatus = .invalid(error.localizedDescription)
        }
    }

    // MARK: - Factory

    /// Returns a configured LLM parser if enabled and key exists, nil otherwise
    func activeParser() -> (any LLMIngredientParser)? {
        guard isLLMEnabled,
              let apiKey = getAPIKey(),
              !apiKey.isEmpty else { return nil }
        return ClaudeIngredientParser(apiKey: apiKey)
    }
}
```

| API key | iOS Keychain | Hardware-encrypted, survives reinstall |
| `connectionStatus` | In-memory | Transient UI state |

## §8 Error Handling

### 8.1 Error-to-Fallback Matrix

| Error | User-Visible Action | Internal Action | Fallback |
|-------|-------------------|-----------------|----------|
| 401 (invalid key) | Alert in Settings only | Log to telemetry, set status `.invalid` | Pipeline |
| 429 (rate limited) | None | 3 retries with exponential backoff (1s, 2s, 4s) | Pipeline after 3 fails |
| 529 (overloaded) | None | 3 retries with exponential backoff | Pipeline after 3 fails |
| 5xx (server error) | None | Log to telemetry | Pipeline |
| Network unavailable | None | Log to telemetry | Pipeline |
| Timeout (15s) | None | Log to telemetry | Pipeline |
| Malformed response | None | Log to telemetry | Pipeline |
| Batch count mismatch | None | Log to telemetry | Pipeline |
| Empty name in result | None | Log to telemetry | Pipeline |

### 8.2 Principle

**The user never sees a parsing failure.** All LLM errors silently fall back to the deterministic pipeline. The only user-visible error is an invalid API key, which is shown in Settings (not during import).

## §11 LLM-Powered Category Prediction (M10.6 Scope Addition)

### Problem

When ingredients are imported, new templates are created with no category. The user must manually assign categories one by one in the `CategoryAssignmentModal`. No prediction or suggestion logic exists today — `parseAndConnectIngredients()` always passes `nil` for category.

### Solution

Add a batch category prediction call during the category assignment flow. When the modal opens with N uncategorized ingredients, send all ingredient names to Claude in a single API call and get back category suggestions.

### Integration Point

**Where**: `CategoryAssignmentModal` (rewritten in M10.3.9 to card-by-card review pattern)

**When**: On modal appear, if LLM is enabled + configured:
1. Collect all uncategorized ingredient names
2. Send batch request to Claude: "Given these grocery categories: [list], assign each ingredient to the most appropriate category"
3. Pre-fill `selectedCategory` for each ingredient card
4. User sees suggestion pre-selected in the category picker — can accept or override

**Prompt design**:
```
You are a grocery categorization assistant. Given these categories:
[Produce, Dairy, Meat & Seafood, Bakery, Spices, Condiments, Canned Goods, ...]

Assign each ingredient to the most appropriate category. Return JSON:
{"garlic powder": "Spices", "chicken breast": "Meat & Seafood", ...}

Ingredients to categorize:
- garlic powder
- chicken breast
- ...
```

**Fallback**: If LLM disabled, fails, or times out → no suggestions, user picks manually (existing M10.3.9 flow)

### Implementation Notes

- Reuse `ClaudeIngredientParser`'s HTTP infrastructure (Keychain API key, retry logic)
- New method: `ClaudeCategoryPredictor.predictCategories(ingredients: [String], availableCategories: [String]) async throws -> [String: String]`
- Or extend the existing `LLMIngredientParser` protocol with an optional `predictCategories` method
- Single API call for all ingredients (not per-ingredient) — keeps cost minimal
- Categories come from the user's actual category list (fetched from Core Data) — not hardcoded

### Estimated Addition: +1-2h on top of M10.6 base estimate

### M10.6.6: User-Triggered AI Parsing Across All Views (9-12h)

M10.6.1-M10.6.4 limited LLM parsing to automatic use during `RecipeImportService.saveImport()`. M10.6.6 adds explicit, user-triggered AI parsing to all ingredient editing surfaces via sparkle buttons and context menus.

#### Architecture: New Public API on IngredientParsingService

Views never call LLM parsers directly. Three new members on `IngredientParsingService`:

```swift
// MARK: - M10.6.6: User-Triggered LLM Parsing

var isLLMAvailable: Bool  // LLMSettingsService.shared.activeParser() != nil

func parseSingleWithLLM(text:source:categories:) async -> (ParsedIngredient, StructuredQuantity, String?)?
func parseBatchWithLLM(texts:source:categories:) async -> [(ParsedIngredient, StructuredQuantity, String?)]?
```

Both return `nil` on any failure — caller keeps existing local result. Single wraps batch (one API call). Telemetry logged internally with `parserUsed: "claude"`. Strict batch validation: count mismatch → return nil.

#### UI Design

**Batch Trigger**: `wand.and.stars` SF Symbol in ingredients section header, trailing position. Visible only when `isLLMAvailable == true`. Disabled when batch in flight or list empty. Loading: swaps to `ProgressView`. Result: in-place update + toast. Failure: toast + data untouched.

**Per-Ingredient**: Context menu "AI Parse" with `wand.and.stars`. Same visibility gate. Loading: per-row spinner. Result: silent in-place update. Failure: spinner stops, data untouched.

**Toast**: Reusable `LLMParsingToast` view modifier — capsule at bottom, auto-dismiss 2s, fade animation.
