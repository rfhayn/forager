# M10.6.14: Fix Category Display + LLM Template Naming

**Status**: ACTIVE
**Priority**: High — user-facing bugs found during build 14 device testing
**Estimated effort**: ~30 min (3 targeted fixes)

## Context

Build 14 (M10.6.13) fixed template visibility — all 20 templates now appear in Ingredients list with correct categories. But device testing revealed two remaining issues:

1. Recipe detail view shows "Choose Category" on 11/20 ingredients despite all templates having categories
2. LLM produces odd template names like "garlic clove" (from "2 cloves garlic") and "lime juice" (from "juice of 2 limes")

## Root Cause Analysis

### Bug A: Category display mismatch

`EditRecipeView.ingredientRow()` passes `categoryName: matchInfo?.categoryName` to `IngredientMatchRow`. The `matchInfo` is computed by re-parsing each ingredient from scratch via `IngredientMatchService.matchBatch()`, which looks up templates by the re-parsed name — NOT by the existing `ingredient.ingredientTemplate` Core Data relationship.

When the re-parsed name differs from the LLM-assigned template name (e.g., local parser produces "garlic" but template is "garlic clove"), the match fails and `categoryName` is nil, showing "Choose Category".

### Bug B: LLM unit words in template names

The LLM prompt instructs singular form but doesn't explicitly exclude unit/count words from ingredient names. Result: "2 cloves garlic" → LLM returns `name: "garlic clove"` instead of `name: "garlic"`.

Additionally, the normalization Phase 0 only strips unit words as **prefixes** ("cloves garlic" → "garlic") but not **suffixes** ("garlic clove" passes through unchanged).

## Fixes

### Fix A: Category fallback to existing template

**File**: `forager/Views/Recipes/EditRecipeView.swift` (line 528)

Add nil-coalescing fallback to use the existing template's category when match-based lookup returns nil:

```swift
// Before:
categoryName: matchInfo?.categoryName,
// After:
categoryName: matchInfo?.categoryName ?? ingredient.template?.category,
```

### Fix B: LLM prompt — exclude unit words from names

**File**: `Services/Parsing/ClaudeIngredientParser.swift` (after line 251)

Add two new rules to the system prompt:

1. "The ingredient name must be ONLY the food item — never include count/unit words like 'clove', 'slice', 'piece', 'wedge', 'head', 'stalk', 'sprig' in the name."
2. "For 'juice of' or 'zest of' patterns, the ingredient is the fruit, not the product."

### Fix C: Suffix unit-word stripping (belt-and-suspenders)

**File**: `Services/IngredientTemplateService.swift` (after Phase 0 prefix stripping)

Add suffix stripping for multi-word names where the last word is a unit word. Guards:
- `words.count >= 2` prevents stripping single-word ingredients (e.g., "clove" the spice)
- Excludes ambiguous words like "head", "ear", "leaf" that can be part of ingredient names

## Verification

- Build succeeds
- Saved imported recipe shows green dots with categories on all ingredients (Fix A)
- New imports produce clean template names like "garlic" not "garlic clove" (Fix B)
- Normalization catches any remaining LLM artifacts (Fix C)
