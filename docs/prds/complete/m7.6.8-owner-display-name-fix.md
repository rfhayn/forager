# M7.6.8: Owner Display Name — Repurpose `ownerEmail` on Household

**Version**: 1.0
**Created**: February 15, 2026
**Completed**: February 15, 2026
**Status**: COMPLETE
**Dependencies**: M7.6.8 (CloudKit Sharing & Household Setup)
**Actual Effort**: ~1.5 hours

---

## Problem Statement

After creating a household and sharing it via CloudKit, the owner's display name shows as empty or "(You)" on the Household Members screen — both on the owner's device and on joinee devices.

### Root Cause (Confirmed by Claude, ChatGPT, and Gemini)

Three interacting platform behaviors combine to break name resolution:

1. **`container.share([household])` only migrates the root record.** When CloudKit shares a Household entity, only the Household itself moves to the shared store. Child records (HouseholdMember) remain in the owner's private store, invisible to other participants.

2. **iOS 16+ strips `nameComponents` from CKShare for the current user.** `share.currentUserParticipant?.userIdentity.nameComponents` returns nil (or empty components) on the owner's device, so `PersonNameComponentsFormatter` produces an empty string.

3. **Empty string ≠ "You".** The existing fallback logic checked for `"You"` or `"User"` but not empty/whitespace strings, so the name lookup was never triggered when `PersonNameComponentsFormatter` returned `""`.

### User Impact

- Owner sees their own name as blank or "(You)" in the Members list
- Joinee devices see the owner's name as blank (HouseholdMember record is in the owner's private store)
- Undermines confidence in the household sharing feature

---

## Solution

Store the owner's display name directly on the Household entity (the shared root record) by repurposing the deprecated `ownerEmail` field. No schema change required.

### Design Decisions

| Decision | Rationale |
|----------|-----------|
| Repurpose `ownerEmail` instead of new field | CloudKit schema is append-only in Production; `ownerEmail` was storing a redundant copy of `ownerRecordName` — free real estate |
| Computed alias `ownerDisplayName` | Clean API without changing the underlying Core Data attribute name |
| Check empty/whitespace in addition to "You"/"User" | iOS 16+ returns empty `nameComponents`, not nil — `PersonNameComponentsFormatter` produces `""` |
| Migration on `loadHousehold()` | Existing households have `ownerEmail` set to a `_`-prefixed recordName; detect and replace with cached display name |

## Changes

### 1. `Household+Extensions.swift` — Computed alias

```swift
public var ownerDisplayName: String? {
    get { ownerEmail }
    set { ownerEmail = newValue }
}
```

### 2. `Household+CoreDataProperties.swift` — Updated comment

Reflects that `ownerEmail` now stores the owner's display name.

### 3. `Services/HouseholdService.swift` — Five changes

| Method | Change |
|--------|--------|
| `createHouseholdAndShare()` | Write `ownerName` (not `ownerIdentifier`) to `ownerDisplayName` |
| `lookupMemberName()` | Added Strategy 3: read `household.ownerDisplayName` before member record and UserDefaults cache |
| `getParticipants()` | Trigger name lookup for empty/whitespace display names, not just "You"/"User" |
| `isOwner()` | Removed `ownerEmail` fallback — uses only `ownerRecordName` |
| `loadHousehold()` | Migration: if `ownerDisplayName` starts with `_` (recordName), replace with cached display name |

### 4. `forager/HouseholdDebugView.swift`

Shows "Owner ID" and "Owner Name" on separate lines.

### 5. Debug print in `dumpHouseholdState()`

Separates identifier from display name in console output.

## Name Resolution Priority (After Fix)

For the **owner** participant:

1. **Household.ownerDisplayName** — shared root record, works cross-device (NEW)
2. **HouseholdMember.displayName** — relationship or direct fetch (may be in private store)
3. **UserDefaults cache** — `cachedOwnerDisplayName`, set during creation
4. **Fallback** — "You" (current user) or "User" (other participant)

For **non-owner** participants: Steps 2–4 (no Household field for non-owners).
