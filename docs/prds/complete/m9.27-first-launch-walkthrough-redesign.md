# M9.27: First Launch Walkthrough Redesign

**Status**: ⏳ PLANNED
**Estimated**: 3.5-5 hours (4 phases)
**Priority**: Launch-blocking
**Depends On**: None (can start immediately)
**Last Updated**: March 21, 2026

---

## Problem Statement

The current first-launch onboarding is a 6-step coach mark overlay that spotlights each tab with brief text descriptions, plus 12 sample recipes, a grocery list, and a meal plan seeded on first launch. Issues:

1. **Coach marks are passive** — users tap through without absorbing information (~20% recall for passive tours vs ~65% for interactive)
2. **Sample data creates confusion** — users can't distinguish sample from real data, and the "Clear Sample Data" button on the final step is a UX red flag
3. **Key features aren't called out** — household sharing and AI API key setup are never surfaced during onboarding
4. **Sample data has technical debt** — ~700 lines in SampleDataSeeder.swift using direct `Entity(context:)` (violates ADR 014), no household scoping, creates edge cases during household creation
5. **Visual style is dated** — the coach marks use `.ultraThinMaterial` glass cards that don't leverage the full Liquid Glass design language

## Research Summary

| Pattern | Recall | Skip Rate | Best For |
|---------|--------|-----------|----------|
| Passive carousel | ~20% | 65-80% | Branding only |
| Coach mark overlays | ~30% | 40-60% | Complex workflows |
| Interactive walkthrough | ~65% | 15-25% | Multi-feature apps |
| Smart empty states | ~70% | N/A (always visible) | Ongoing discovery |
| Apple TipKit | Contextual | N/A | Progressive disclosure |

**Apple HIG guidance**: "Let people jump right in." Maximum 3 screens if a welcome is needed. Use empty states as the primary teaching mechanism.

**Competitor analysis**:
- **Paprika**: No onboarding, drops into empty recipe list — trusts UI simplicity
- **AnyList**: 3-screen carousel → grocery list with pre-populated categories
- **Mealime**: Asks dietary preferences → auto-generates meal plan → shows grocery list (best-in-class)
- **Yummly**: Taste quiz → personalized recipe feed

## Solution: 3-Screen Welcome + Enhanced Empty States

### Design Philosophy

Remove sample data entirely. Replace the 6-step coach mark overlay with a 3-screen welcome carousel that sets context, then let enhanced empty states teach each feature in-place. Keep coach marks available for "Replay Onboarding" in Settings.

**Why no sample data:**
- The existing empty states with `ContentUnavailableView` + action buttons already tell users what to do
- Sample data has 15-25% higher Day 1 retention BUT higher Day 7 churn (research finding)
- Removing ~700 lines eliminates ADR 014 violations and household-scoping edge cases
- DefaultSeeder's 7 categories (Produce, Dairy, etc.) stay — these are infrastructure, not samples

## Phase Breakdown

### Phase 1: Welcome Carousel (2-2.5 hours)

**Create `forager/Views/Settings/WelcomeWalkthroughView.swift`:**
- 3-screen `TabView(.page)` with ForagerTheme styling
- SF Symbols + ForagerTheme color tokens
- Skip link, page dots, "Get Started"/"Continue"/"Let's Go" buttons
- Sets `hasCompletedOnboarding = true` on final button

### Phase 2: Remove Sample Data (30-45 minutes)

- **Delete** `Services/Persistence/SampleDataSeeder.swift`
- **Remove** `SampleDataSeeder.seedSampleDataIfNeeded(in:)` call from `PersistenceController.swift` `performOneTimeSetup()`
- **Remove** from `OnboardingView.swift`:
  - `SampleDataSeeder.hasSampleData` conditional text
  - "Clear Sample Data" button and associated logic
  - `SampleDataSeeder.clearSampleData(in:)` call
- **Leave** UserDefaults keys as inert (existing users who cleared data unaffected)

### Phase 3: Enhanced Empty States (45-60 minutes)

- `WeeklyListsView.swift`: add secondary description to empty state
- `MealPlanListView.swift`: add contextual guidance to empty state
- Review RecipeListView empty state (likely already sufficient)

### Phase 4: Wire Up & Polish (30-45 minutes)

- `foragerApp.swift`:
  - Replace `CoachMarkOverlay` ZStack with `.fullScreenCover(isPresented: .init(get: { !hasCompletedOnboarding && isReady }, set: { _ in }))`
  - Keep `.onReceive(NotificationCenter.default.publisher(for: .replayOnboarding))` for coach mark replay
- Test fresh install flow end-to-end
- Test "Replay Onboarding" from Settings still shows coach marks
- Test existing user (flag already set) sees no welcome

## Risk Assessment

| Risk | Severity | Mitigation |
|------|----------|------------|
| Empty tabs feel less impressive than populated | Medium | Welcome carousel sets expectations; empty states have action buttons |
| Existing users with `hasCompletedOnboarding = false` see new welcome | Low | Only fresh installs or users who never completed onboarding |
| Orphaned UserDefaults keys from SampleDataSeeder | None | Keys become inert; no cleanup needed |
| "Replay Onboarding" shows different flow than first launch | Low | Intentional — coach marks are a feature refresher, welcome is a brand intro |
