## 🚨 Problem Statement

### **Current Pain Points**

#### **1. Scattered Save Responsibilities**

**Current state:**
```swift
// Views calling save() directly
Button("Save") {
    viewContext.save()  // ❌ View owns persistence
}

// Services sometimes saving, sometimes not
func createHousehold() {
    // Creates household but caller must save ❌
}
```

**Problems:**
- ❌ Hard to track where writes happen
- ❌ Difficult to add validation hooks
- ❌ Impossible to test without full persistence stack
- ❌ Error handling inconsistent

#### **2. Boolean Sheet Chaos**

**Current state:**
```swift
@State private var showingAddIngredient = false
@State private var showingEditRecipe = false
@State private var showingDeleteConfirm = false
@State private var showingShareSheet = false
// ... 5+ more booleans per screen
```

**Problems:**
- ❌ Can show multiple sheets simultaneously (bugs)
- ❌ Hard to track navigation state
- ❌ Deep linking nearly impossible
- ❌ Code duplication across screens

#### **3. Inconsistent Empty States**

**Current state:**
```swift
// Screen A
if recipes.isEmpty {
    Text("No recipes yet")
}

// Screen B
if ingredients.isEmpty {
    VStack {
        Image(systemName: "list.bullet")
        Text("No ingredients")
    }
}

// Screen C
// Nothing - just blank screen ❌
```

**Problems:**
- ❌ Inconsistent UX
- ❌ Some screens show nothing when empty
- ❌ Code duplication

#### **4. Known Issues from M7.2.2 Testing**

**Bug: Member Count Not Refreshing After CloudKit Sync**

**Current state:**
```swift
// SettingsView.swift:101
Text("\(household.members?.count ?? 0)")  // ❌ Doesn't re-observe after sync
```

**Observed behavior:**
- Device A creates household, invites Device B
- Device B accepts invitation, member created successfully
- Device A shows member count of "1" until force-close
- Clicking into members list shows correct 2 members
- Force-close updates count to "2"

**Root cause:**
- SwiftUI not re-observing `household.members` relationship after CloudKit import
- Data is correct in Core Data
- View observation pattern missing CloudKit change notifications

**Impact:**
- Visual only, no functional impact
- Data syncs correctly
- Count shows correctly after force-close or navigation

**Fix:**
- Option A: Use `@FetchRequest` for member count instead of computed property
- Option B: Add `.id(household.objectID)` to force view refresh
- Option C: Observe CloudKit sync notifications and trigger manual refresh

**Discovered**: M7.2.2 physical device testing (Jan 12, 2026)
**Priority**: Low (polish issue, no data corruption)
**Recommendation**: Fix in Phase 2 (Navigation & UI) of M7.5

#### **Chunk 1.2: Create Service Write Methods** (1.5 hours)

**Objective:** Add intent-style methods to services

**Pattern:**
```swift
// ❌ OLD: View saves directly
Button("Add Ingredient") {
    let template = IngredientTemplate(context: viewContext)
    template.name = name
    template.category = category
    try? viewContext.save()
}

// ✅ NEW: Service owns write
@EnvironmentObject var ingredientService: IngredientTemplateService

Button("Add Ingredient") {
    ingredientService.createTemplate(name: name, category: category)
}

// In IngredientTemplateService:
func createTemplate(name: String, category: Category?) {
    let context = persistence.newBackgroundContext(for: .userEdit)
    
    let template = HouseholdIngredientTemplateRepository.getOrCreate(
        displayName: name,
        category: category,
        household: currentHousehold,
        in: context
    )
    
    do {
        try context.save()
        print("✅ Template created: \(name)")
    } catch {
        print("❌ Failed to create template: \(error)")
        // Publish error to view
    }
}
```

### **Phase 2: SwiftUI Navigation Cleanup** (3-4 hours)

**Goal:** Replace boolean sheet flags with enum-based routing

#### **Chunk 2.1: Enum-Based Routing (GroceryListView)** (2 hours)

**Objective:** Convert highest-complexity screen to enum routing

**Implementation:**
```swift
// BEFORE: Boolean soup
@State private var showingAddIngredient = false
@State private var showingEditItem = false
@State private var showingShareSheet = false

// AFTER: Single enum
enum Sheet: Identifiable {
    case addIngredient
    case editItem(GroceryListItem)
    case share(WeeklyList)
    
    var id: String {
        switch self {
        case .addIngredient: return "add"
        case .editItem(let item): return "edit-\(item.id?.uuidString ?? "")"
        case .share(let list): return "share-\(list.id?.uuidString ?? "")"
        }
    }
}

@State private var activeSheet: Sheet?

// Usage
.sheet(item: $activeSheet) { sheet in
    switch sheet {
    case .addIngredient:
        AddIngredientView()
    case .editItem(let item):
        EditItemView(item: item)
    case .share(let list):
        ShareSheet(list: list)
    }
}

// Trigger
Button("Add") {
    activeSheet = .addIngredient
}
```

**Acceptance:**
- [ ] Same UI flows
- [ ] No duplicate presentations
- [ ] Code clearer to read
- [ ] Deep linking possible (future)

#### **Chunk 3.1: Create EmptyStateView** (1 hour)

**Objective:** Reusable component for empty screens

**Implementation:**
```swift
struct EmptyStateView: View {
    let icon: String
    let title: String
    let message: String
    var action: (() -> Void)? = nil
    var actionLabel: String = "Get Started"
    
    var body: some View {
        VStack(spacing: 20) {
            Image(systemName: icon)
                .font(.system(size: 60))
                .foregroundColor(.secondary)
            
            Text(title)
                .font(.title2)
                .fontWeight(.semibold)
            
            Text(message)
                .font(.body)
                .foregroundColor(.secondary)
                .multilineTextAlignment(.center)
                .padding(.horizontal)
            
            if let action = action {
                Button(action: action) {
                    Label(actionLabel, systemImage: "plus.circle.fill")
                }
                .buttonStyle(.borderedProminent)
            }
        }
        .padding()
    }
}
```

**Usage:**
```swift
if recipes.isEmpty {

        icon: "fork.knife",
        title: "No Recipes Yet",
        message: "Start building your recipe collection",
        action: { showingAddRecipe = true },
        actionLabel: "Add Recipe"
    )
}
```

**Acceptance:**

#### **Chunk 3.3: Core Data Invariant Tests** (2 hours, OPTIONAL)

**Objective:** Minimal test coverage for critical invariants

**Create:** `foragerTests/CoreDataInvariantsTests.swift`

**Required Tests (5-10 total):**
```swift
import XCTest
@testable import forager

class CoreDataInvariantsTests: XCTestCase {
    var persistence: PersistenceController!
    var context: NSManagedObjectContext!
    
    override func setUp() {
        persistence = PersistenceController(inMemory: true)
        context = persistence.viewContext
    }
    
    // Test 1: Default seeding is idempotent
    func testDefaultSeedingIdempotency() throws {
        let seeder = DefaultSeeder()
        
        // Seed once
        try seeder.seedDefaultsIfNeeded(context: context)
        let firstCount = try context.count(for: Category.fetchRequest())
        
        // Seed again
        try seeder.seedDefaultsIfNeeded(context: context)
        let secondCount = try context.count(for: Category.fetchRequest())
        
        XCTAssertEqual(firstCount, secondCount, "Seeding should be idempotent")
        XCTAssertEqual(firstCount, 7, "Should have 7 default categories")
    }
    
    // Test 2: Category normalization prevents duplicates
    func testCategoryNormalizationUniqueness() throws {
        let household = Household(context: context)
        household.id = UUID()
        household.name = "Test"
        
        let cat1 = HouseholdCategoryRepository.getOrCreate(
            displayName: "Produce",
            household: household,
            in: context
        )
        
        let cat2 = HouseholdCategoryRepository.getOrCreate(
            displayName: "produce",
            household: household,
            in: context
        )
        
        XCTAssertEqual(cat1.id, cat2.id, "Should return same category")
    }
    
    // Test 3: Delete category reassigns ingredients
    func testCategoryDeleteReassignment() throws {
        // Create household
        let household = Household(context: context)
        household.id = UUID()
        household.name = "Test"
        
        // Create categories
        let produce = HouseholdCategoryRepository.getOrCreate(
            displayName: "Produce",
            household: household,
            in: context
        )
        
        let other = HouseholdCategoryRepository.getOrCreate(
            displayName: "Other",
            household: household,
            in: context
        )
        
        // Create template in Produce
        let template = IngredientTemplate(context: context)
        template.id = UUID()
        template.displayName = "Basil"
        template.category = produce
        template.household = household
        
        try context.save()
        
        // Delete Produce
        context.delete(produce)
        try context.save()
        
        // Template should be reassigned
        XCTAssertEqual(template.category, other, "Template should reassign to Other")
    }
    
    // Add 2-7 more tests for:
    // - Ingredient template uniqueness
    // - Planned meal slot enforcement
    // - Recipe scaling
    // - Quantity merging
    // - Household member validation
}
```

**Acceptance:**
- [ ] All tests pass
- [ ] Tests run in <5 seconds
- [ ] No CloudKit dependencies
- [ ] Easy to add more tests
