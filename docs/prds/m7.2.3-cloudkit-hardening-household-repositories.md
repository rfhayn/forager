## 🎯 Executive Summary

M7.2.3 hardens CloudKit integration and prevents duplicate data creation in household-scoped shared zones. This milestone combines two critical improvements:

1. **Persistence Layer Decomposition**: Break up the complex 400+ line Persistence.swift into focused, testable components
2. **Household-Scoped Repositories**: Implement semantic uniqueness for household-shared entities to prevent duplicate categories, templates, and planned meals

**Why This Matters:**
- **Race Condition Prevention**: Multiple household members creating "Produce" category simultaneously
- **Idempotent Seeding**: Default data creation safe after CloudKit imports
- **Testability**: Decomposed persistence makes M7.2.2 (member invitation) testing deterministic
- **Foundation for External Beta**: Clean architecture before M7.6 (TestFlight submission)

**Key Deliverables:**
- `PersistenceController` (focused on container/store management only)
- `DefaultSeeder` (idempotent default data creation)
- `MigrationRunner` (one-time migrations tracked in Core Data metadata)
- `CloudKitDiagnostics` (observes and tracks CloudKit events)
- `HouseholdCategoryRepository`, `HouseholdIngredientTemplateRepository`, `HouseholdPlannedMealRepository`
- Standardized merge policy strategy across all contexts
- CloudKit test harness UI for deterministic manual testing

## 🚨 Problem Statement

### **Current Pain Points**

#### **1. Persistence.swift Complexity (400+ lines)**
```swift
// Current state: Everything in one file
class PersistenceController {
    - Container setup
    - Store loading
    - CloudKit configuration
    - Default seeding
    - Migrations
    - CloudKit event observation
    - Sample data
    - Debug helpers
}
```

**Problems:**
- ❌ Hard to understand what runs when
- ❌ Race conditions between seeding and CloudKit imports
- ❌ Difficult to test individual components
- ❌ Merge policy confusion (ad-hoc context creation)
- ❌ Cannot deterministically test household sharing flows

#### **2. Duplicate Data Creation in Household Shared Zones**

**Scenario:**
```
Sarah (Owner): Opens app → Creates "Produce" category → Saves to CloudKit
Mike (Member): Opens app simultaneously → Creates "Produce" category → Saves to CloudKit

Result: Two "Produce" categories in shared household zone
App Crash: "Fatal error: Duplicate values for key: 'Produce'"
```

**Root Cause:** CloudKit only understands UUID uniqueness, not semantic uniqueness (same name = same thing).

#### **3. Merge Policy Inconsistency**

**Current state:**
- viewContext: Sometimes store-trump, sometimes object-trump
- Background contexts: Inconsistent policy application
- Seeding contexts: No explicit policy set
- Migration contexts: No explicit policy set

**Problem:** Unpredictable behavior during concurrent household member edits.

### **Phase 2: Household-Scoped Repository Pattern** (4-5 hours)

**Goal:** Prevent duplicate data creation in household shared zones

#### **Phase 2.1: HouseholdCategoryRepository (1.5 hours)**

**Create:** `forager/Repositories/HouseholdCategoryRepository.swift`

**Features:**
- Query by `normalizedName` + `household`
- Return existing if found
- Create new only if doesn't exist
- Set all semantic keys automatically

**Implementation:**
```swift
struct HouseholdCategoryRepository {
    /// Gets existing or creates new category within household scope
    /// Prevents duplicate "Produce" categories in same household
    static func getOrCreate(
        displayName: String,
        household: Household,
        in context: NSManagedObjectContext
    ) -> Category {
        let normalized = displayName.lowercased().trimmingCharacters(in: .whitespacesAndNewlines)
        
        // Query by semantic key + household
        let request: NSFetchRequest<Category> = Category.fetchRequest()
        request.predicate = NSPredicate(
            format: "normalizedName == %@ AND household == %@",
            normalized, household
        )
        request.fetchLimit = 1
        
        // Return existing or create new
        if let existing = try? context.fetch(request).first {
            print("📦 Found existing category: '\(displayName)' in household '\(household.name ?? "Unknown")'")
            return existing
        }
        
        print("✨ Creating new category: '\(displayName)' in household '\(household.name ?? "Unknown")'")
        let category = Category(context: context)
        category.id = UUID()
        category.name = displayName
        category.normalizedName = normalized
        category.household = household
        category.updatedAt = Date()
        return category
    }
}
```

#### **Phase 2.3: HouseholdPlannedMealRepository (1.5 hours)**

**Create:** `forager/Repositories/HouseholdPlannedMealRepository.swift`

**Features:**
- Query by `slotKey` (date + mealType) + `household`
- Enforce one meal per slot per household
- Update recipe if slot already filled

**Implementation:**
```swift
struct HouseholdPlannedMealRepository {
    /// Gets existing or creates new planned meal for specific slot
    /// Enforces one meal per date+mealType per household
    static func getOrCreate(
        date: Date,
        mealType: String,
        recipe: Recipe?,
        mealPlan: MealPlan?,
        household: Household,
        in context: NSManagedObjectContext
    ) -> PlannedMeal {
        // Validate mealType
        let validTypes = ["breakfast", "lunch", "dinner", "snack"]
        let normalized = mealType.lowercased()
        guard validTypes.contains(normalized) else {
            fatalError("Invalid mealType: \(mealType). Must be: \(validTypes.joined(separator: ", "))")
        }
        
        // Create slot key
        let formatter = ISO8601DateFormatter()
        formatter.formatOptions = [.withFullDate]
        let dateString = formatter.string(from: date)
        let slotKey = "\(dateString)-\(normalized)"
        
        // Query by slot key + household
        let request: NSFetchRequest<PlannedMeal> = PlannedMeal.fetchRequest()
        request.predicate = NSPredicate(
            format: "slotKey == %@ AND household == %@",
            slotKey, household
        )
        request.fetchLimit = 1
        
        if let existing = try? context.fetch(request).first {
            print("📦 Found existing meal for slot '\(slotKey)' in household '\(household.name ?? "Unknown")'")
            if existing.recipe != recipe {
                print("🔄 Updating recipe for slot '\(slotKey)'")
                existing.recipe = recipe
            }
            return existing
        }
        
        print("✨ Creating new meal for slot '\(slotKey)' in household '\(household.name ?? "Unknown")'")
        let meal = PlannedMeal(context: context)
        meal.id = UUID()
        meal.date = date
        meal.mealType = normalized
        meal.slotKey = slotKey
        meal.recipe = recipe
        meal.mealPlan = mealPlan
        meal.household = household
        meal.createdDate = Date()
        return meal
    }
}
```

### **Phase 3: Merge Policy Standardization & Test Harness** (3-4 hours)

**Goal:** Consistent merge policies and deterministic testing

#### **Phase 3.1: Standardize Merge Policies (1.5 hours)**

**Define Strategy:**
```swift
// PersistenceController.swift
private func configureViewContext() {
    // User-facing context: Store wins (CloudKit is source of truth)
    viewContext.mergePolicy = NSMergeByPropertyStoreTrumpMergePolicy
    viewContext.automaticallyMergesChangesFromParent = true
}

// HouseholdService.swift (or any service creating background contexts)
func newBackgroundContext(purpose: ContextPurpose) -> NSManagedObjectContext {
    let context = container.newBackgroundContext()
    
    switch purpose {
    case .userEdit:
        // User edits: Object trump (preserve user intent)
        context.mergePolicy = NSMergeByPropertyObjectTrumpMergePolicy
    case .seedingOrMigration:
        // Seeding/migrations: Store trump (don't overwrite existing)
        context.mergePolicy = NSMergeByPropertyStoreTrumpMergePolicy
    }
    
    return context
}

enum ContextPurpose {
    case userEdit
    case seedingOrMigration
}
```

**Document in code comments:**
```swift
/*
 MERGE POLICY STRATEGY:
 
 viewContext (UI):
 - NSMergeByPropertyStoreTrumpMergePolicy
 - CloudKit is source of truth for concurrent edits
 - Prevents UI from overwriting other household members' changes
 
 Background contexts (User edits):
 - NSMergeByPropertyObjectTrumpMergePolicy
 - Preserves user intent when saving
 - User's edit wins if conflict with store
 
 Background contexts (Seeding/Migrations):
 - NSMergeByPropertyStoreTrumpMergePolicy
 - Don't overwrite existing data
 - Safe for idempotent operations
 */
```
